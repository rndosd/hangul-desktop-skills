# 새 문서의 첫 저장 보존 후보

맑은 고딕·기본 함초롬 두 글꼴을 가진 단일 새 문서만 검증 대상으로 한다. python-hwpx6.3.0과 실제 확인한 Malgun TTF 해시/PANOSE가 필요하다. 다른 글꼴 파일·한글 빌드·PC는 별도 검증 대상이다. 파일·설정·DLL 설치는 없다.

create_new_document.compose는 HwpxDocument.new 직후 생성 생명주기를 등록한다. 공개 header.element/mark_dirty 어댑터가 맑은 고딕 typeInfo를 설치 글꼴의 OS/2와 공식 예제로 확인하고, 언어별 글꼴 순서/ID/전체 charPr fontRef를 일관되게 준비한다. 문단 현대 분기의 의도 값은 유지하며 새 문단의 호환 분기 여백만 두 배, PERCENT 줄간격의 unit만 HWPUNIT으로 기록한다. 이는 13.0.0.3903의 관찰값이며 과거 엔진 호환성 인증은 아니다.

새 목록 생성 중 본문 참조가 없어진 문단 정의는 삭제하지 않는다. 원래 정의 전체를 지키는 PARA 스타일 “작성 보존 문단서식 ID”를 공개 ensure_style로 추가한다. 문서 스타일 목록에 항목이 보인다. 기존 문서에는 이 생성 경로를 호출하지 않는다. 모듈은 등록되지 않은 문서를 거부하고, 단위/분기/글꼴/이름 충돌/160스타일 제한을 확인한다. 실제 저장에서 참조/모든 정의가 보존되는지와 같은 파일의 재편집·전체 PDF는 여전히 별도 필수 검사다.

생성 audit는 현대 의도 값과 두 배 호환 값 양쪽을 확인한다. 저장 비교기는 바꾸지 않는다. 모든 raw 패키지 차이를 기록하고 첫 저장·반복 저장의 active+전체 정의, 저장된 파일의 실제 네 여백 변경을 독립적으로 확인한다. PDF 같음을 파일 보존으로 보고하지 않는다.

근거: [한컴 공식 글꼴/문단 구조 예제](https://tech.hancom.com/python-hwpx-parsing-2/)의 맑은 고딕 typeInfo. 호환 여백 배수·단위·미사용 정의 삭제·정렬은 실제 원본6종의 첫 저장 실패에서 확인한 동작이며 해당 공식 글이 이를 보장한다고 주장하지 않는다.
