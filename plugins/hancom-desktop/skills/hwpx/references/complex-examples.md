# 실제 업무처럼 복잡한 구조를 시험하는 예시

이 문서의 프롬프트와 날짜·수량·기관·역할은 모두 가상 시험 자료다. 사용자 요청을 대신하는 고정 목차나 필수 형식이 아니다.

## 짧은 작성 요청 + 별도 자료

> 첨부 메모로 사업장 통합 이전 계획서 만들어줘. 팀장 보고용이고, 일정·담당·업무 공백 대책까지 보기 좋게 정리해줘.

첨부 메모에 상담석·장비·자료 수량, 예산 한도, 일정별 담당, 제외 기준, 예외와 점검 항목을 제공한다. 프롬프트가 짧더라도 원자료는 충분하다. 없는 숫자와 확정 사실을 자동으로 채우는 시험으로 해석하지 않는다.

## 구체적이지만 자연스러운 변경 요청

> 이 계획서 수정해줘. 23일 일괄 이전을 자료·비품은 23일, 필수 장비는 24일로 나누고, 원격근무 장비 대여는 취소해줘. 임시 상담 창구·예비 전화와 전환 승인 절차도 추가해줘. 인계표는 비상 연락을 한 칸으로 합치고 운영 공지는 담당을 따로 적게 나눠줘. 결재란과 대상 목록은 유지하고, 자세한 변경 메모도 반영해줘.

모델은 요약·판단 조건·일정·예외·인수 점검 사이의 관계를 함께 읽는다. 표의 행만 고쳐 놓고 본문에 취소된 일괄 이전을 남기는 결과는 실패다. 판단 조건과 앞쪽 요약도 같은 변경에 맞춰 수정한다.

## 검증된 사례와 범위

- 기입된 원본 5쪽, 새 문서 작성 6쪽, 원본 수정 6쪽. 각 7개 표와 두 수준의 native 제목 번호.
- 기존 수정은 정확한 원문과 행 전체를 확인한 뒤 28개 제한 연산을 연결했다. 일정 8→12, 예외 6→7, 점검 12→16건.
- 결재·대안 비교·대상 목록은 전체 XML이 동일하다. 지정하지 않은 본문과 패키지도 동일하다.
- 가로 병합 전 구분·담당·내용을 한 문장으로 보존한다. 분할 후 새 빈 문단에 담당과 안내를 각각 입력한다.
- 실제 한글 2024 저장·재열기·PDF 출력과 독립 보존 검사를 통과했다. 새 작성과 기존 수정의 최종 페이지 픽셀이 모두 일치한다.

이것은 작성 에이전트가 기존 제한 helper를 조합한 복합 사례다. `content_structure.py existing`의 빈 영역 전용 계약을 기입된 문서 전체의 자동 변형 API로 확대하지 않는다. 서로 다른 열 수 재구성, 임의 세로 병합, 복잡한 개체의 재배치 등 미지원 범위는 지원되지 않는다.

입력·기입된 원본·결과: [예시 자산](../assets/complex-structure/). `prompts.md`에서 전체 가상 변경 메모를 읽는다. 이 한 사례의 보고서 목차·페이지 나눔·행 높이를 모든 문서에 강제하지 않는다.

## 셀 분할의 비기본 세로 정렬

python-hwpx 6.3.0의 `split_merged_cell`은 새 셀의 세로 정렬을 CENTER로 만든다. 원본이 TOP/BOTTOM이면 `safe_cell_layout.py`가 새 빈 셀에만 원래 정렬을 복원한다. 전체 독립 검증은 계속 켜져 있으며, 다른 속성이나 비대상 셀이 달라지면 출력하지 않는다. 세 정렬·범위 오류·원문 충돌·무관 속성 손상의 회귀 시험을 포함한다.
