# 내용에 따라 기존 표의 항목 추가·삭제하기

사용자의 짧은 요청을 보고 문서의 문맥과 변경자료를 먼저 읽는다. 실제 대상, 종료/추가 항목, 삽입 순서, 보존할 데이터와 서식, 긴 문구의 역할을 명시한다. 특정 내용 구성을 의무로 강제하지 않는다. 의미 판단은 에이전트가 하며 이 바인더는 자연어 해석기가 아니다.

`semantic_table_binding.bind(source, headers, key, source_sha256=None)`는 읽기 전용이다. 첫 행의 정확한 전체 머리글 배열로 유일한 표를 찾고, key는 머리글 이름→셀 전체 문구로 지정한다. 셀의 여러 문단은 개행으로 구분한다. 부분 문자열/행 순번/첫 번째 일치/중복 단계명만으로 추측하지 않는다. 반복되는 ‘준비’ 대신 정확한 실행업무와 담당을 함께 지정한다. 여러 표나 행이 맞으면 추가 근거가 필요하다. 파일 해시·표 ID·전체 표 fingerprint·현재 행과 문단/run 모형을 반환한다.

`row_request(source,binding,operation,parameters,reason)`는 현재 소스를 다시 비교하고 기존 [부분 표 구조 편집](mixed-table-structure.md)의 요청을 만든다. operation=delete_row 또는 clone_after. 수동 row override는 받지 않는다. clone_after의 parameters는 전체 cells와 heightHwpunit이며 **복사하는 행 바로 뒤에 삽입한다**. 별도 삽입 위치와 별도 donor를 지원한다고 해석하지 않는다. 원하는 순서에 알맞은 기존 행을 선택하거나 검증된 새 행을 다음 donor로 사용한다. 작업 하나 후에는 새 파일에서 다시 bind한다. 예전 해시/순번을 재사용하지 않는다.

완전한 단순 data row만 이 바인더의 변경 대상으로 지원한다. 병합셀·중첩/알 수 없는 컨트롤·보호 셀은 기존 가드로 거부한다. 문서의 다른 영역에 있는 병합표나 결재칸은 보존하며 그 존재만으로 원래 지원되는 단순 표의 편집을 막지 않는다. 의미가 같다는 이유로 실제 데이터 행을 합치거나 삭제하지 않는다.

새 내용은 [문단 문구 매핑](paragraph-payload.md)으로 글머리표·강조·단서 등의 역할을 보존한 전체 셀/run 지도를 만들고 독립 기대값과 비교한다. 설명 길이에 따라 새 행의 최소 높이를 정하되 실제 한글 출력으로 조정한다. 단어가 잘리거나 숨은 내용이 생기면 쪽 나눔/행 크기를 검토한다. 페이지 수를 맞추려고 전체 글씨·쪽 여백을 무조건 줄이지 않는다.

기존 original row의 전체 셀/문단/run서식·폭·테두리·병합·자산·다른 표와 본문을 대조한다. 원본은 보존한다. 실제 저장본에 같은 의미별 편집을 다시 적용하고, 저장 전/저장본 재열기/재저장 PDF 전체 픽셀과 내부 active/모든 공유 정의를 별도로 비교한다. native가 표 전체 높이를 다시 계산했다면 strict FAIL을 남기고 원인을 읽기 전용으로 설명하며 PDF 동일성으로 내부검사를 면제하지 않는다. 긴 표 반복 머리행과 뒤 본문 여백·실제 목차를 확인하고 모든 실제 지면을 검토한다.

읽기 전용 CLI: `scripts/semantic_table_binding_cli.py --source SOURCE.hwpx --request REQUEST.json`. schema=hwpx.semantic-table-binding.v1, headers=정확한 배열, key=정확한 셀 문구 객체, sourceSha256=선택적 고정 해시. 문서 생성/COM 성공을 뜻하지 않는다. 검증 범위는 이 단순 행 바인딩과 기존 엔진의 허용 범위이며 모든 양식/다른 PC/모델의 판단 효과는 별도 검증한다.
