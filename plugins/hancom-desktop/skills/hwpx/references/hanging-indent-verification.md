# 번호 다음 줄의 내어쓰기 검수

번호 시작 위치(계층 0/1/2칸)와 번호 뒤 본문 시작 위치는 별도 기준이다. 번호를 본문 문자로 쓰거나 선행 공백으로 맞추지 않는다. 새 문서는 native NUMBER/BULLET와 공유 번호 정의를 사용한다. 기존 문서의 번호 체계는 요청 없이 변환하지 않는다.

`create_new_document.py audit`는 번호 정의·수준·그룹 재시작·문단 왼쪽 위치와 `autoIndent=1`을 검사한다. 제목 번호와 본문 항목 모두 대상이다. `tests/test_hanging_indent.py`는 긴 제목/항목 생성, 재열기, 번호 본문 비삽입, 자동 내어쓰기 손상 검출을 시험한다. 이 검사는 실제 줄바꿈 정렬의 증거가 아니다.

실제 검수는 다음과 같이 수행한다.

1. 검토할 최종 HWPX의 SHA-256을 기록하고 `hwpx-windows-finalize` 경로로 그 파일에서 PDF를 출력한다. 다른 판의 PDF를 재사용하지 않는다.
2. 긴 번호 제목·번호 항목·가운데점 항목을 각 수준에서 두 줄 이상으로 출력한다. 한 줄로 끝나면 줄바꿈 검증은 NOT_CHECKED로 남긴다. 번호가 두 자리로 늘어나는 경계도 실제 사용하는 문서에서 확인한다.
3. 첫 줄의 번호 다음 **본문 첫 글자**와 두 번째 이후 줄의 첫 글자 왼쪽 위치를 대조한다. 둘째 줄이 번호 자체의 시작 위치로 돌아가면 실패다. PDF 좌표 측정과 해당 쪽 시각 검토를 함께 기록한다.
4. 표 안 항목·쪽을 넘어가는 항목은 사용한 경우 별도로 확인한다. 번호 누락/중복, 그룹 재시작, 글꼴 대체, 잘림도 확인한다.
5. 문서/PDF 해시, 한글 버전, 쪽 번호, 첫 줄/이어지는 줄 위치, 허용 오차와 판정, 검토 캡처를 남긴다. 실제 한글을 실행할 수 없으면 `PASS_STRUCTURE / NATIVE_WRAP_NOT_CHECKED`로 보고한다.

이 통합판은 구조 회귀 검증을 포함한다. 오늘 생성본의 실제 한글/PDF 줄 정렬 검증은 완료되지 않았다. 과거 실험의 NOT_CHECKED를 성공으로 바꾸지 않는다.
