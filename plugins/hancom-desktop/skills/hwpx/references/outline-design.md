# 조립 개요 설계: 주제만 받아도 보고서 틀 세우기

사용자는 보통 "○○ 운영계획서 만들어줘"처럼 주제와 몇 가지 내용만 말하고 틀은 말하지 않는다. 조립(`assemble`)은 정한 요소를 잘 배치하지만 어떤 요소를 쓸지는 개요가 정한다. 개요를 쓰기 전에 아래 순서로 틀을 세운다. 고정 목차를 베끼지 않고, 내용의 생김새에 따라 요소를 고른다.

## 1. 문서 종류와 독자를 정한다

요청에서 문서 종류(운영계획·사업계획·결과보고·검토보고)와 읽는 사람(결재권자·교직원·학부모 등)을 한 문장으로 정한다. 종류가 모호하면 제목 낱말(계획·보고·결과·방안)로 판단한다.

## 2. 내용 재료를 만든다

사용자가 준 사실을 모두 넣고, 그 주제를 실제로 운영할 때 필요한 내용을 **제안**으로 채운다. 활동 방법·운영 절차·유의점·역할·평가 방법은 주제에 맞게 구체적으로 쓴다(제안은 사실 조작이 아니다). 모르는 값만 비운다.

- 날짜·금액·인원·사람 이름처럼 확인해야 하는 값은 `○월 ○일`, `○○명`, `○○○원`, `담당: ○○○`처럼 자리로 남긴다. 값 자리는 표 칸에 두어도 된다.
- 결과보고는 실적을 만들지 않는다. 사용자가 준 실적만 쓰고, 없으면 실적 표의 값 칸을 `○○`로 두고, 성과는 무엇을 근거로 볼지(활동지·설문·참여 기록 등)를 쓰되 결과를 단정하지 않는다.
- "이는 가상 예시이다", "실제 수치는 포함하지 않았다" 같은 단서 문장을 본문에 넣지 않는다. 미정·제안 상태는 끝 보고에서 사용자에게 알린다.

## 3. 빠지기 쉬운 항목을 점검한다

아래는 순서표가 아니라 점검표다. 장 구성은 사용자 내용이 정하고, 여기서는 빠진 것만 찾는다. 주제와 맞지 않으면 빼고, 주제 고유의 항목(예: 운동회의 우천 시 대책, 체험학습의 이동 계획)은 더한다.

| 종류 | 점검할 항목 |
|---|---|
| 운영계획 | 근거·필요성, 목적, 방침, 개요(일시·장소·대상), 세부 활동, 역할 분담, 추진 일정·절차, 예산, 안전·유의 사항, 평가·환류, 기대 효과 |
| 사업계획 | 배경·현황, 추진 방향, 과제별 내용, 추진 일정, 예산, 성과 지표, 관리·점검 |
| 결과보고 | 개요(기간·대상·내용), 추진 경과, 실적(계획 대비), 성과, 문제점·한계, 개선·후속 조치 |
| 검토보고 | 검토 배경, 현황·문제, 대안 비교, 권고안, 필요한 결정·후속 절차 |

## 4. 내용의 생김새로 요소를 고른다

같은 내용이라도 생김새에 맞는 요소로 쓴다. 이것이 문서 모양을 정한다.

| 내용의 생김새 | 요소 (`t`) |
|---|---|
| 장을 나누는 큰 주제 | `chapter` |
| 장 안의 독립된 덩어리(과제·활동 영역·학년별 운영) | `task`(①②), 공문서형은 `heading` 1 |
| 번호 없이 묶는 짧은 머리(근거·목적·방침) | `subhead`, 그 아래 한두 문장 요지는 `lead` |
| 덩어리 안의 항목 | `item` |
| 한 항목의 세부·예시 | `dash`, 그 아래는 `dot` |
| 주의·근거·참고 | `note` |
| 결과·연결("그래서") | `arrow` |
| 꼭 전할 한 문장 | `box` |
| 단계가 이어지는 흐름(준비→운영→평가) | 표 `steps` 또는 `schedule` |
| 날짜·할 일·담당이 반복 | 표 `schedule` |
| 대상·학년·영역마다 같은 항목 비교 | 표 `grid`·`targets` |
| 과제별 지표·목표값 | 표 `indicators` |

- 양식에 없는 요소는 대신 그려지며(`substitutions`), 고를 때 미리 `assemble --template ID --describe`로 갖춘 역할·표를 확인한다.
- 양식 폴더의 `reproduction/outline.json`은 그 양식의 완성형 문서가 요소를 어떻게 섞는지 보여 주는 예다. 요소 조합을 참고하되 문구·순서를 베끼지 않는다.

## 5. 쓰기 전에 모양을 점검한다

- 한 장이 `item`만 여러 개(대략 6개 이상) 이어지면 덩어리(`task`·`heading`)로 나누거나 세부를 `dash`로 내릴 수 있는지 본다.
- 문서에 표가 하나도 없으면 일정·역할·대상·예산 중 표로 쓸 반복 자료가 없는지 본다. 억지로 표를 만들지는 않는다.
- 같은 문장 꼴("~하였다")이 길게 반복되면 개조식(명사형·"~함")으로 줄인다.
- 분량 요청(예: 5~6쪽)은 덩어리·세부·표 내용을 늘려 맞춘다. `pageBreakBefore`로 쪽을 늘리지 않는다. 쪽 나눔은 표지·요약처럼 원래 새 쪽이 맞는 곳에만 쓴다.

## 6. 출력 뒤 확인과 보고

`pageLayout`의 `PAGE_GAP`(쪽 아래가 크게 빔)이 있으면 원인(쪽 나눔·통째로 넘어간 표)을 고쳐 다시 만든다. 경고가 남은 채 완료라고 보고하지 않는다. 쪽 이미지를 보고, 끝 보고에는 제안으로 채운 부분과 `○○`로 남긴 값을 짧게 알린다.
