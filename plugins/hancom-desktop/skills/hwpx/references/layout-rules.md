# 공통 서식 규칙과 검사

기본 제공 양식 3종과 새로 등록하는 양식이 함께 따르는 목록·제목 서식 규칙이다. 표지·색·제목 띠·표 모양·큰 제목 장치(번호 띠, `Ⅰ.`)는 양식별 디자인으로 두고, 아래 규칙만 공통으로 맞춘다. 계획서·보고서에서 널리 쓰는 `□ → ○ → - → ·` 관행과 [업무 문서 기준](document-basics.md)의 번호·내어쓰기 원칙을 검사할 수 있는 형태로 옮긴 것이다. 공문 기안문의 법정 항목 기호·위치는 [업무 문서 기준](document-basics.md#번호와-문단)을 따른다.

| 규칙 | 내용 | 검사 위치 |
|---|---|---|
| R1 | 목록 항목이 줄을 넘기면 둘째 줄은 첫 줄의 **본문 첫 글자** 아래에서 시작한다(허용 0.6mm). | 한글 PDF |
| R2 | 목록 항목은 왼쪽 정렬이다. 양쪽 정렬은 기호 뒤 공백을 늘려 R1을 깨뜨린다. | HWPX |
| R3 | 같은 단계·같은 기호의 항목과 번호 제목은 정렬·왼쪽 여백·내어쓰기·줄간격·기호 앞 공백 수·기호 글자 서식이 같다. 문단 앞뒤 간격은 위치(쪽 첫 제목 등)에 따라 달라질 수 있어 비교하지 않는다. | HWPX |
| R4 | 아래 단계 항목은 위 단계 항목보다 오른쪽에서 시작한다. | 한글 PDF |
| R5 | 항목 기호는 원형(❍·◦·○, 1단계) → `-`·`⇒`(2단계) → `·`(3단계) 순서로 쓴다. 번호 소제목(①) 아래에는 1단계 항목 또는 `⇒` 설명을 둘 수 있다. | HWPX |
| R6 | 목록 항목 본문은 문서 안에서 한 가지 글자 서식(글꼴·크기·자간·굵기)을 쓴다. 굵게는 일부 단어 강조에만 쓰고, 그런 항목은 비교에서 뺀다. | HWPX |
| R7 | 항목·번호 제목의 기호와 앞 공백은 한컴 옛 글꼴(HFT: HCI Poppy·한양신명조 등)이 아닌 TrueType 글꼴로 그린다. 옛 글꼴은 PC·한글 판에 따라 다른 글꼴로 대체되어 기호 폭이 달라지고, 한 PC에서 맞춘 내어쓰기가 다른 PC에서 어긋난다. | HWPX |

## 검사 방법

공통 실행기에서 다음 명령을 쓴다. 결과의 `warnings`는 검토할 위치이며 쓰기를 막지 않는다.

```powershell
& $taskLauncher layout-check 문서.hwpx                       # R2·R3·R5·R6·R7
& $taskLauncher layout-check 문서.hwpx --pdf 한글출력.pdf      # 위 + R1·R4
```

- `fill`은 결과 문서에 R2·R3·R5·R6·R7을 자동으로 검사해 `layoutRules`로 알린다.
- `preview`와 `finalize_document.py run`은 PDF의 R1·R4를 `wrapAlignment`로, 아래 쪽 배치 점검을 `pageLayout`으로 알린다. 시각 검수의 참고이며 완료 판정은 기존 검토 기록이 한다.
- R1은 실제로 줄이 넘어간 항목만 확인할 수 있다. `NOT_CHECKED`는 통과가 아니다. 긴 항목이 없는 문서는 긴 예시로 한 번 출력해 확인한다.
- 검사 범위는 표 밖 본문이다. 표 안 항목은 출력 화면으로 확인한다.

## 쪽 배치 점검

한글 PDF에서 `page_layout.py`가 측정하며 `layout-check --pdf`·`preview`·`finalize`가 함께 보고한다. 기준값은 점검용이며 모든 문서의 규칙은 아니다.

| 코드 | 뜻 | 먼저 할 조치 |
|---|---|---|
| LAST_PAGE_SPARSE | 마지막 쪽에 3줄 이하만 남음 | 앞쪽 제목·표 앞뒤 간격이나 빈 문단을 줄여 한 쪽을 줄인다. 내용을 지우거나 글자·자간을 압축하지 않는다. 줄이기 어려우면 그대로 두고 보고한다. |
| PAGE_GAP | 표지·요약이 아닌 쪽 아래가 40% 이상 빔 | 강제 쪽 나눔·“다음 문단과 함께”·통째로 넘어간 표가 원인인지 확인하고, 원본 분량에 맞춘 쪽 나눔이면 지운다. |
| TABLE_SPLIT_THIN | 같은 표가 쪽 경계에서 1행만 남고 나뉨 | 짧은 표는 “나누지 않음”(`pageBreak="NONE"`), 긴 표는 행 단위 나눔과 머리행 반복을 쓴다. |
| SHORT_TAIL | 한두 글자만 다음 줄로 넘어감(목록 항목의 둘째 줄 포함) | 단어 중간에서 갈렸으면(`반 / 영`) 그 문단을 [어절 줄바꿈](word-flow.md)으로 바꿔 단어째 넘긴다. 단어째 넘어간 짧은 꼬리는 [자간 후보](word-flow.md#자간-후보를-선택할-때)를 -1부터 작게 비교해 윗줄에 붙는 것만 고른다. 좁은 표 칸은 열 너비를 다시 나눈다. 둘 다 효과가 없을 때 문구를 다듬는다. |
| BOLD_MIX | 같은 기호 항목의 굵기가 섞임(R6) | 항목 본문을 보통 굵기로 맞추고 강조는 일부 단어에만 쓴다. |
| HEADING_WRAP | 번호 제목(①·□) 둘째 줄이 본문 첫 글자보다 왼쪽 | 해당 제목 서식에 번호 폭만큼 내어쓰기를 준다. |

## 어긋났을 때

- R2·R3·R6: 같은 역할 문단이 한 가지 문단·글자 서식을 쓰도록 기존 편집 경로로 맞춘다. 공백 문자로 위치를 흉내 내지 않는다.
- R7: 해당 글자 서식의 옛 글꼴을 내어쓰기를 맞춘 PC에서 실제로 그려진 TrueType 글꼴(PDF의 글꼴 이름으로 확인)로 바꾼 뒤, R1을 다른 판의 한글에서도 출력해 확인한다.
- R1: 왼쪽 정렬을 먼저 확인하고, 내어쓰기 값을 측정한 차이만큼 조정한다(1mm ≈ 283 HWPUNIT). 저장된 줄 배치(`linesegarray`)가 옛 값으로 남아 있으면 한글이 그대로 쓰므로 해당 문단의 줄 배치를 지우고 다시 출력한다.
- 양식 자체의 문제는 [완성형 등록](complete-template-registration.md) 단계에서 고친다. 기본 제공 3종은 저장소의 `tools/normalize_template_layout.py`와 `tools/rebuild_template_references.py`로 이 규칙을 적용하고 한글 출력으로 확인했다. 3종 모두 목록·본문은 어절 줄바꿈이다.
