# 실사용 문서의 수정과 필요한 개선

일반 문서 작성·수정은 SKILL.md의 기본값으로 진행한다. 이 참조는 결과가 기대와 다르거나 원인 분석·재발 방지를 요청받았을 때 사용한다. 스킬명이나 “루프”라는 명시적 표현은 필수가 아니다.

## 현재 결과를 먼저 고치기

원래 요청, 전달한 정확한 파일, 사용자 피드백과 실제 출력에서 기대와 다른 부분을 좁힌다. 사용자가 원인을 설명할 필요는 없다. “학교 안내문 느낌이 아니다”처럼 기준이 추상적이면 독자·용도에 맞는 구체적인 수정안을 먼저 만들고, 방향을 결정할 선호가 실제로 부족할 때만 짧게 묻는다. 명시적 요청은 기관 서식 관행이나 기본안보다 우선한다.

| 확인된 원인 | 처리할 곳 | 확인할 결과 |
|---|---|---|
| 요구 누락·문구·구성·표현·가독성 | 현재 문서와 작성 계획 | 원래 요구 및 수정 피드백 충족, 필요한 실제 출력 |
| COM 시작·임시 폴더 권한·잠금·시간 초과 | 실행 환경과 현재 작업 경로 | 정상 실행과 같은 후보의 검증; 문서 손상으로 단정하지 않음 |
| 검사 기준·도구 오류 | 검사기 또는 검사 해석 | 원래 실패 기록, 기준의 타당한 근거, 올바른 사례와 결함 사례 구분 |
| 여러 작업에서 반복되는 작성·편집 방법의 결함 | 재발 방지용 도구·템플릿·스킬 | 재현 사례에서 예방하고 정상 사례도 처리함 |

내용·레이아웃 실패, 미지원 연산, 자동화 장애, 내부 구조 진단을 분리한다. XML이나 해시 차이만으로 사용자 결과 실패를 단정하지 않는다. 실제 출력이 같아도 비대상 구조·재편집 보존 등 작업상 필요한 검사를 임의로 없애지 않는다.

현재 문서의 문제는 요청 범위 안에서 수정하고 필요한 부분을 재검증한다. 기준을 낮추거나 실패 영수증을 바꿔 성공으로 만들지 않는다. 같은 원인의 실행 실패 재시도는 SKILL.md의 제한을 따른다. 레이아웃 후보는 원인이나 변경 범위가 다른 경우에만 비교하고, 개선이 없으면 축소·압축을 계속하지 않는다. 필요한 정보나 지원이 없으면 마지막으로 확인된 파일과 남은 문제를 전달한다.

## 실행과 대기를 줄이기

여러 작업이 한글을 공유하면 입력 블록·편집 요청·실행 명령이 준비된 뒤 실행 순서를 요청한다. 앞으로 한글이 필요하다는 이유만으로 사용 순서를 선점하지 않는다. 대기 중에도 가능한 내용·로컬 편집을 진행하고, 실제 실행 가능한 상태에서 기다린 시간만 한글 대기로 구분한다. 기존 native 실행기의 소유권·동시 실행 방지는 유지한다.

내용과 구조가 정해진 변경은 기존 다중 편집으로 묶고, 준비된 블록은 공통 조합 명령으로 이어 실행한다. 구체적인 배치 불확실성이 있으면 중간 출력으로 확인하되 모든 작은 수정마다 재출력하지 않는다. 이미 나온 정확한 저장본·영수증·PDF를 최종 검토에 재사용하고, 이후 변경된 후보에만 관련 확인을 갱신한다.

## 공통 스킬 개선이 필요한 경우

문서 한 건을 고쳐 달라는 요청은 그 문서의 수정 범위다. 반복을 막거나 한글 스킬을 개선해 달라는 요청 및 이미 승인된 개선 프로그램이 있으면 해당 범위의 재발 방지를 진행한다. 기존 승인을 다시 묻지 않는다. 범위가 부족하면 현재 문서 수정을 끝내고 구체적인 공통 변경안을 제시한다.

반복 사례 또는 명확한 공통 결함의 근거가 있을 때 가장 작은 예방 수단을 고른다. 단일 원자료·템플릿·검사기로 막을 수 있으면 그것을 우선하고, 판단의 문제는 짧은 지침으로 남긴다. 일회성 취향이나 가상 행사 정보를 모든 문서의 규칙으로 올리지 않는다. 근거 있는 회고·재발 방지는 이 문서의 원인 분류·수정·검증 절차와 해당 업무의 기존 플레이북에서 처리한다. 설치 스킬 수정은 `skill-creator` 기준에 따라 필요한 범위에서 수행한다. 이미 수행한 회고·검사를 별도 절차로 중복 실행하지 않는다.

수정 전 파일과 실패 근거를 보존한다. 바뀐 방법으로 해당 문제와 관련 정상 사례를 확인하고, 실제 실행 검증과 지침 검토를 구분해 기록한다. 전역 스킬 수정은 허용된 대상·권한 안에서 수행하며 한글 설치·보안 설정 변경, 다른 프로젝트 작업, 외부 전송으로 확대하지 않는다.

검증 범위는 변경의 영향과 미확인 위험으로 정한다. 기존 구조·입출력·보존 조건을 유지하는 중복 호출 제거나 일괄 처리 연결은 관련 회귀시험과 대표 실문서의 전후 동등성으로 확인한다. 이미 검증한 같은 결과를 얻었다면 같은 native 검증을 반복하지 않는다. 문서 내용·배치가 바뀌거나 기존 근거로 판단할 수 없는 차이가 생기면 해당 후보를 실제 한글에서 확인한다. 표 병합·소유 위치·보존 판정·저장과 복구 경계가 바뀌면 그 위험에 맞춰 독립 검토와 실제 실행 범위를 넓힌다.

작은 변경에 설계안 경쟁·별도 검토 에이전트·전체 회귀를 관례로 추가하지 않는다. 빠르게 실행되는 관련 자동시험은 유지하고, 같은 목적의 조사와 검토부터 합친다. 문구·참조 연결 수정은 해당 문구와 링크 확인으로 마치며 새 실행 경로를 만든 경우에만 그 경로를 실행한다. 완료한 사용자 산출물은 추가 스킬 개선이 끝날 때까지 보류하지 않고 먼저 전달한다.

기록은 기존 작업 자료에 `기대 결과 / 관찰된 문제 / 원인 / 최소 수정 또는 무수정 판단 / 검증 근거 / 다음 실제 사용에서 확인할 점`을 필요한 만큼 남긴다. 지침 부족·기존 지침 불이행·도구/환경 결함·원인 미확인을 구분한다. 기록만 완료, 수정·검증 완료, 실제 사용 효과 확인을 구분하고 다음 관련 업무에서 결과를 확인해 절차를 유지·수정·단순화한다. 업무 지도에는 기준 스킬과 상태 기록의 연결만 두며 상세 기록을 복제하지 않는다. 기록 저장은 자동 학습·자동 반영·예약 실행을 뜻하지 않는다. 해결됐거나 요청된 개선이 끝나면 종료한다.

이 PC의 2026-10-26 원본 연결·실행 경로 개선은 [로컬 작업 기록](<local-path>)에 원인·검증·적용 대상을 남겼다. 이는 해당 설치본의 사례 기록이며 새 문서의 품질 인증이나 다른 배포본의 변경 완료를 뜻하지 않는다.
