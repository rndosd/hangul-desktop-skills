# 업무 상황별 회귀 시험

짧은 자연어 요청과 별도 가상 메모를 함께 제공한 통합 시험이다. 모든 수치·날짜·역할은 합성 시험 조건이다. 시험 목차, 표 선택과 행 높이를 실제 문서의 필수 형식으로 강제하지 않는다.

## 확인한 결과

2026-10-03, Windows / 한글 2024 13.0.0.3903 / Python 3.12 / python-hwpx 6.3.0.

| 상황 | 최종 | 확인점 |
| --- | --- | --- |
| 구매 검토 | 1쪽 | 견적 비교, 조건 차이와 미정 사항, 승인 전 목록 |
| 장애 경위 | 2쪽 | 시간 순서, 확정 사실과 추정 구분, 후속 조치 |
| 긴 교육 일정 | 3쪽 | 24행, 모든 쪽의 표머리 반복과 행 연속성 |
| 회의 결과 | 1쪽 | 표 없이 결정·보류 목록, 여러 줄 내어쓰기 |
| 행사 축소 | 수정 전 2쪽 / 후 2쪽 | 프로그램 8→3행, 본문 동시 갱신, 결재·안전 표 보존 |
| 병합 점검표 | 수정 전 2쪽 / 후 2쪽 | 두 셀 수정, 가로·세로 병합 머리글과 다른 상태 보존 |

총 8문서 15쪽의 실제 한글 열기·저장·재열기·PDF 출력, 독립 텍스트/활성 서식/표 구조 검사와 전체 쪽 시각 검사를 통과했다. 최종 예시 6건과 기존 원본 2건의 strict completion gate가 complete다. COM 생성과 RegisterModule은 별도 호출이며, 현재 worker는 보안 등록 실패 시 열기 전에 중단한다. PASS_FULL은 두 단계가 모두 성공해야 가능한 경로이고, 등록 반환값을 별도 receipt 필드로 기록하지는 않는다. 보안·DLL·레지스트리 설정은 변경하지 않았다.

## 사례에서 얻은 조정 원칙

- 구매 표의 최소 본문 행 높이 22→15mm만 줄여 2→1쪽으로 정리했다. 글자와 쪽 여백은 유지했다. 자료가 적은데 긴 고정 높이를 주면 마지막 목록만 다음 쪽으로 밀릴 수 있다.
- 장애 경위 표의 높이 18→16mm로 조정하니 설명 문단의 쪽 경계 분할이 해소됐다. PDF 추출 스트림이 문단의 앞·뒤 사이에 표 텍스트를 배치할 수 있다. 단일 문자열 검색 실패를 내용 유실로 단정하지 말고 XML 원문/페이지별 좌표/실제 화면을 함께 대조한다. 내용을 통째로 검사에서 제외하지 않는다.
- 긴 교육 표와 병합 점검표는 실제 다음 쪽에 전체 표머리가 나타나는지 검사했다. repeatHeader 속성만 보고 완료하지 않는다.
- 행사 축소는 결재·안전 표 전체의 보존을 우선했다. 내용이 줄어도 보호 표의 높이 때문에 둘째 쪽이 남는다. 쪽 수가 반드시 줄어든다고 약속하지 않는다. 보호 범위를 바꾸려면 사용자의 변경 요청을 받아야 한다.
- 입력의 숫자 검사는 분기 숫자를 원자료에 명시하지 않은 fixture를 차단했다. 입력을 정정했고 검사 기준을 약화하지 않았다. 점검표 기대값의 분기 인덱스를 잘못 설정한 시험 드라이버도 독립 비교가 잡았으며, helper의 대상 좌표는 맞았다. 이를 편집 엔진의 오류로 기록하지 않는다.

## 현재 한계와 중단 조건

8개 거부 시험에서 원본 유지/결과 미발행을 확인했다: 오래된 원본 해시, 내용이 있는 비기준 셀 병합, 병합 영역 일부만 분할, 병합표 열 폭 변경, 병합표 본문 행 높이 변경, 표머리 삭제, 다른 문서에 바인딩된 텍스트 계획, 빈 영역 실행기에 기입된 영역 전달.

기입 양식 변형은 작성 에이전트가 정확한 원문/대상 좌표/보호 범위를 판단하고 기존 제한 helper를 조합한 사례다. `content_structure.py existing`은 여전히 빈 반복 영역 계약이다. 미지원 병합표/열 재구성을 임의 XML 변경으로 우회하지 않는다.

초기 6개 후보는 첫 한글 저장에서 꼬리말 paraPr 참조가 변경돼 원래 strict gate가 blocked 상태로 남았다. 전체 참조 정의와 나머지 control/활성 서식이 동일함을 독립 검증한 다음 실제 한글 저장본을 새로운 입력으로 별도 재검증했다. 초기 차단 증거를 덮어쓰거나 gate를 완화하지 않았다. 초기 작성기의 참조 정규화 자체는 미해결이며, 다른 control 차이를 이 원인으로 자동 분류하지 않는다.

6개 에이전트 작성 fixture는 다양한 외부 문서의 성공률을 뜻하지 않는다. 실제 사용자 양식과 글꼴·개체·서식 변형은 추가 검증이 필요하다.

## 재사용과 증거

[입력·출력 자산](../assets/scenario-suite/)의 `prompts.md`에는 짧은 요청과 전체 별도 메모, 구체적 변경 조건이 있다. `manifest.json`은 원자료 계획과 파일을 연결한다. `validation-summary.json`과 `guard-results.json`은 이 PC에서의 관찰 기록이며 다른 PC의 실행 결과가 아니다.

다른 PC에서 재시험할 때는 승인된 환경을 확인하고 원본 복사본에서 새 계획·대상 바인딩·해시를 만든다. `source-plans/*.json`의 새 작성 계획은 지원된 공통 실행기로 검증·작성할 수 있다. 행사/점검표의 기입된 `before.hwpx`를 수정할 때는 각각 명시된 보존 영역을 독립 비교한다. 병합 점검표 원본을 단순 새 작성 계획만으로 재생성했다고 주장하지 않는다. 각 결과를 설치된 한글에서 별도로 저장·재열기·PDF 출력하고 모든 쪽을 검토하여 새 completion 증거를 얻는다. 번들 안의 과거 complete 기록으로 새 PC의 정상 작동을 판단하지 않는다.
