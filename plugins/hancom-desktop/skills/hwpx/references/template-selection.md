# 기본형과 사용자 양식 선택

## 선택 순서

1. 사용자 제공 원본과 개인 등록 양식을 우선한다. 원본은 보존하고 새 사본에서 작업한다.
2. 지정 양식이 없는 계획서·결과보고·행사 안내는 아래 [조립 양식 6종](#조립-양식-고르기) 중 하나를 골라 조립한다.
3. 그중 적합한 것이 없는 문서(회의록·가정통신문 등)는 사용자 양식을 받아 기존 편집 도구로 준비한다. 옛 원본·합본·작은 블록 목록으로 자동 대체하지 않는다.

기본형은 디자인과 입력 위치를 준비한 문서다. 목차·쪽수·항목 수를 새 내용에 무조건 강제하지 않는다. 사용자 양식 등록은 한 번 준비하고 이후 재사용한다.

## 준비된 완성형 계획서

색인은 `assets/document-templates/full-plans.json`이다. 원본과 별도의 준비본·입력 연결·한글 출력 예시를 묶었으며 공통 fill의 `--catalog`로 바로 사용한다. 매번 모든 원본이나 세 문서의 내부를 읽지 않는다. 내용 구성과 아래 짧은 설명으로 하나를 고른 뒤 그 항목의 입력만 조회한다.

| ID | 용도 | 원본·준비 범위 |
|---|---|---|
| `plan-school` | 학교 교육활동·행사 운영계획 | **작성은 [학교형 조립](simple-entry.md#양식별-차이) `assemble --template plan-school`이 기본이다**(□ 막대·탭·과제 수 자유, 4단계 절차표). 행복마을학교 원본에서 준비한 이 fill 준비본(표지 없는 개요·운영·준비지원·일정평가, 기본 2쪽, 운영 활동 구역 1~6개)은 조립 부품의 원본이며 예비다 |
| `plan-education` | 교육사업·프로그램 추진계획 | **작성은 [교육사업형 조립](simple-entry.md#양식별-차이) `assemble --template plan-education`이 기본이다**(표지 쪽, □ 막대·현황표·탭·과제 수 자유). 사회적경제 교육 원본에서 준비한 이 fill 준비본(표지·현황표·교육활동·지원·관리평가, 기본 3쪽, 교육활동 영역 1~6개)은 조립 부품의 원본이며 예비다 |
| `plan-project` | 여러 과제를 둔 종합 추진계획 | **작성은 [사업형 조립](simple-entry.md#양식별-차이) `assemble --template plan-project`가 기본이다**(같은 디자인, 과제·탭·표 수 자유, 같은 분량이면 완성형과 같은 쪽 배치). 이 fill 준비본(표지·요약·과제 3개 고정)은 조립 부품의 원본이며, 조립이 실패했을 때만 예비로 쓴다 |

장·절 수가 내용마다 다른 공문서형 시행·운영계획(Ⅰ. / 1. / 가. / ○ 체계)은 완성형 fill 대신 [개요 조립](simple-entry.md#개요로-조립) `assemble --template plan-official`을 쓴다. 사업형(요약 쪽, Ⅰ 띠·번호 탭·네모 번호 과제)·학교형·교육사업형도 길이와 관계없이 각 ID의 `assemble`을 쓴다. 같은 내용이면 완성형과 같은 서식·쪽 수로 나온다.

### 조립 양식 고르기

사용자가 모양을 말하지 않으면 문서의 쓰임으로 고른다. 공문서형이 어느 내용에나 맞아 보여도 기본값으로 삼지 않는다.

| 이런 문서면 | 양식 | 알아보는 단서 |
|---|---|---|
| 교내 행사·교육활동·학년/학급 운영계획(교내 결재용, 몇 쪽) | `plan-school` | 행사·주간·축제·체험·동아리·학급, 교내 담당자가 작성 |
| 대상·프로그램별로 나뉜 교육사업 추진계획(표지가 있는 제출용) | `plan-education` | 연수·캠프·방과후·지원사업·프로그램, 대상별 운영, 외부 기관·교육청 제출 |
| 여러 과제를 묶은 종합·중장기 계획(요약 쪽이 필요한 분량) | `plan-project` | 종합·기본·중장기·혁신·추진과제, 과제가 셋 이상, 성과지표 |
| 기관 단위 시행계획·공문 붙임 계획(여러 쪽) | `plan-official` | 시행·실시·평가·선발·점검, 1.·가.·1) 단계가 깊음 |
| 조사·운영 결과를 1~2쪽으로 요약(결과보고, 실태조사, 점검 결과) | `report-brief` | 결과·실태·현황·분석, □ 개요/주요 결과/개선방향, 결과 표 |
| 행사·방문·회의 개최 계획이나 안내(1쪽 개요와 프로그램) | `event-plan` | 개최·방문·설명회·포럼·연수 안내, 일시·장소·참석자, 시간별 프로그램 |

- 둘 이상에 걸치면 독자와 제출처를 먼저 본다(교내 → 학교형, 외부 제출 → 교육사업형·공문서형).
- 짧은 행사(과제 1~2개)에 사업형을 쓰면 요약 쪽이 비기 쉽다. 1쪽짜리 행사 안내는 `event-plan`, 결과를 몇 쪽으로 정리하면 `report-brief`.
- 결과보고서는 `report-brief`(1~2쪽) 또는 `plan-official`(여러 쪽, 경과·실적·성과·개선을 장으로 나눔)로 쓴다. `plan-project`는 계획용이라 요약 쪽이 비므로 결과보고에 쓰지 않는다.
- 끝 보고에 고른 양식과 이유를 한 줄로 알리고, 다른 양식으로 바꿀 수 있다고 덧붙인다. 같은 개요로 `--template`만 바꿔 다시 조립하면 된다.

예비로 fill을 쓸 때 활동·과제 수가 양식 칸과 다르면 `sections`로 구역을 늘리거나 빼고([공통 fill](simple-entry.md#준비된-완성형-계획서-채우기)), 넣을 자리가 없는 내용은 버리지 말고 알린다. 과제가 1~2개인 짧은 행사에 종합사업형을 쓰면 요약·일정 쪽이 비기 쉽다.

쪽수는 빈 준비본의 출력 관측이며 채운 분량에 따라 늘어난다. 원래 기관명·사업명·연도·금액은 일반 입력 안내로 정리했다. 같은 제목·기관·요약/상세 값은 `valueFrom`으로 연결되어 한 번만 입력한다. 반복 문단과 표 행은 필요한 수만 채운다. 구역 색인은 준비본의 현재 경로와 해시에 묶이며 원본의 위치 기록은 `sourceRegions`로 따로 남긴다. 임의 구역 조합을 미리 합격시킨 것은 아니다.

`plan-project`는 원본 인쇄 옵션의 영향 때문에 이 PC의 단순 PDF SaveAs가 두 쪽씩 출력되는 한계가 남아 있다. 검증 PDF는 [한컴 공식 안내](https://forum.developer.hancom.com/t/saveas-pdf/1670/2)의 `PrintToPDFEx`, `PrintMethod=0`, 출력 `FileName`을 사용했다. 해당 준비본의 `preparation.pdfExport`와 검증 영수증을 따른다. 이를 원본 인쇄 설정의 영구 수정 성공으로 보고하지 않는다.

새 완성형 양식을 추가하거나 교체할 때는 [완성형 등록 안내](complete-template-registration.md)를 따른다. 원본 보관과 준비 완료를 구분하고, 등록 준비를 일반 작성마다 반복하지 않는다.

## 작성과 검수

[원본 기반 작성](source-template-reuse.md)과 [공통 fill](simple-entry.md#준비된-완성형-계획서-채우기)을 따른다. 자료에 없는 사실은 미정으로 표시하고 새 내용에 맞게 문단·표를 조정한다. 사용자 원본의 역할은 보존·변형·참고 중 요청에 맞춰 정하며, 필수 조건과 비대상 서식을 지킨다. `.hwp`는 필요하면 [변환 경로](workflows-hwp-conversion-windows.md)로 HWPX 사본을 만든다.

과거 원본 파일과 검증 기록은 출처 확인용으로 보존하지만 현재 작성 후보가 아니다. 최종 내용·수치·서식·실제 한글 출력을 확인한다. 신규 생성 프리셋이나 과거 목록을 실패의 자동 대체 경로로 사용하지 않는다.
