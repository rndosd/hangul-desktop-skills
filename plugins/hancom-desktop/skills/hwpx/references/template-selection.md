# 기본형과 사용자 양식 선택

## 선택 순서

1. 사용자 제공 원본과 개인 등록 양식을 우선한다. 원본은 보존하고 새 사본에서 작업한다.
2. 지정 양식이 없는 계획서는 아래 완성형 기본형 3종 중 하나를 고른다.
3. 적합한 기본형이 없는 보고서·안내문·회의문서 등은 사용자 양식을 받아 기존 편집 도구로 준비한다. 옛 원본·합본·작은 블록 목록으로 자동 대체하지 않는다.

기본형은 디자인과 입력 위치를 준비한 문서다. 목차·쪽수·항목 수를 새 내용에 무조건 강제하지 않는다. 사용자 양식 등록은 한 번 준비하고 이후 재사용한다.

## 준비된 완성형 계획서

색인은 `assets/document-templates/full-plans.json`이다. 원본과 별도의 준비본·입력 연결·한글 출력 예시를 묶었으며 공통 fill의 `--catalog`로 바로 사용한다. 매번 모든 원본이나 세 문서의 내부를 읽지 않는다. 내용 구성과 아래 짧은 설명으로 하나를 고른 뒤 그 항목의 입력만 조회한다.

| ID | 용도 | 원본·준비 범위 |
|---|---|---|
| `plan-school` | 학교 교육활동·행사 운영계획 | 행복마을학교 원본. 표지 없는 개요·운영·준비지원·일정평가, 기본 2쪽 |
| `plan-education` | 교육사업·프로그램 추진계획 | 사회적경제 교육 원본. 표지·현황표·교육활동·지원·관리평가, 기본 3쪽 |
| `plan-project` | 여러 과제를 둔 종합 추진계획 | 지역인재육성지원사업 원본. 표지·사업 요약·상세과제·일정표·성과지표·역할, 기본 5쪽 |

쪽수는 빈 준비본의 출력 관측이며 채운 분량에 따라 늘어난다. 원래 기관명·사업명·연도·금액은 일반 입력 안내로 정리했다. 같은 제목·기관·요약/상세 값은 `valueFrom`으로 연결되어 한 번만 입력한다. 반복 문단과 표 행은 필요한 수만 채운다. 구역 색인은 준비본의 현재 경로와 해시에 묶이며 원본의 위치 기록은 `sourceRegions`로 따로 남긴다. 임의 구역 조합을 미리 합격시킨 것은 아니다.

`plan-project`는 원본 인쇄 옵션의 영향 때문에 이 PC의 단순 PDF SaveAs가 두 쪽씩 출력되는 한계가 남아 있다. 검증 PDF는 [한컴 공식 안내](https://forum.developer.hancom.com/t/saveas-pdf/1670/2)의 `PrintToPDFEx`, `PrintMethod=0`, 출력 `FileName`을 사용했다. 해당 준비본의 `preparation.pdfExport`와 검증 영수증을 따른다. 이를 원본 인쇄 설정의 영구 수정 성공으로 보고하지 않는다.

새 완성형 양식을 추가하거나 교체할 때는 [완성형 등록 안내](complete-template-registration.md)를 따른다. 원본 보관과 준비 완료를 구분하고, 등록 준비를 일반 작성마다 반복하지 않는다.

## 작성과 검수

[원본 기반 작성](source-template-reuse.md)과 [공통 fill](simple-entry.md#준비된-완성형-계획서-채우기)을 따른다. 자료에 없는 사실은 미정으로 표시하고 새 내용에 맞게 문단·표를 조정한다. 사용자 원본의 역할은 보존·변형·참고 중 요청에 맞춰 정하며, 필수 조건과 비대상 서식을 지킨다. `.hwp`는 필요하면 [변환 경로](workflows-hwp-conversion-windows.md)로 HWPX 사본을 만든다.

과거 원본 파일과 검증 기록은 출처 확인용으로 보존하지만 현재 작성 후보가 아니다. 최종 내용·수치·서식·실제 한글 출력을 확인한다. 신규 생성 프리셋이나 과거 목록을 실패의 자동 대체 경로로 사용하지 않는다.
