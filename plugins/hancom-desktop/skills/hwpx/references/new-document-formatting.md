# 번호·정렬·간격 설계

이 통합판의 집계 표와 번호·항목 들여쓰기는 [v2 규칙](new-document-v2.md)을 우선 적용한다. 수동 `indent_left_mm` 예시는 사용자 명시 서식의 예외 또는 과거 호환 경로다.

## 긴 문서와 작성 양식

문서 길이는 필요한 설명·일정·산출·기준·양식으로 확보하고 반복 설명·큰 여백·빈 행으로 쪽수를 맞추지 않는다. 6~8쪽 같은 요청은 native 렌더 전에는 목표로만 기록한다. 본문은 자연스럽게 이어지게 하고, 배포·작성 용도가 다른 부록은 이유가 있을 때만 계획된 쪽 나눔을 둔다.

긴 표는 동일 속성을 한 표에서 비교하는 목적을 유지한다. 제목 반복은 표의 repeatHeader와 첫 행의 제목 셀 설정을 함께 저장한다. `page_break:'CELL'`은 셀 내부 텍스트까지 쪽을 넘어 나누는 설정이고 `TABLE`은 셀/행 사이에서 나누는 설정이다. 긴 표는 `treat_as_char:false`를 명시한다. [쪽 흐름·간격·여백](page-flow.md)을 먼저 읽으며 실제 행·셀의 이동과 남는 공간은 화면에서 검사해야 한다. 표를 담는 문단은 뒤 문단과 함께 유지하지 않도록 하고 크기 보호·압축 줄바꿈으로 긴 내용을 숨기지 않는다.

작성용 표에는 `row_heights_mm`로 제목 행을 포함한 행별 높이를 지정할 수 있다. 값 개수는 전체 행 수와 같아야 하고 각 값은 5~60mm이다. 개인 기록·성찰·피드백을 쓰는 공간에만 사용하고 본문 분량을 늘리는 빈 행으로 쓰지 않는다. 새 표의 전체 높이와 각 셀 높이를 저장 후 대조하며 실제 줄 수에 따른 확장·쪽 경계는 native 검사 대상이다.

일정·차시·인원·모둠·자료 수량·예산 산식·평가 코드·부록 참조를 같은 구조화된 가상 원자료에서 연결한다. ‘미확인’과 0점을 구분하고 미확인 항목이 있으면 평가 합계를 보류하도록 한다. 가상 수치를 실제 출석·집행·성과로 옮기지 않는다.

공식 참고: [한글 표의 여러 쪽 지원과 제목 반복](https://help.hancom.com/hoffice130_assistant/ko-KR/Hwp/table/tableattribute/table%28table%29.htm), [셀 입력과 크기 고정](https://help.hancom.com/hoffice/multi/ko_kr/hwp/table/tableattribute/table%28cellattribute%29.htm). 저장 설정 검사와 실제 한글 동작 확인을 구분한다.

## 문서 품질을 먼저 판단하기

### 병렬 항목과 설명을 구분하기

상위 제목 아래의 대상·목적·운영 내용처럼 나란히 검토할 세부 항목에는 선택된 번호 체계의 다음 수준을 적용한다. 같은 속성을 나열하는 짧은 제안에는 가운데점 글머리표를 사용한다. 앞 항목의 해석·제약·이유를 이어 설명하는 문단까지 기계적으로 번호화하지 않는다. 번호 기능을 보여 주기 위해 내용을 추가하지 않는다. 작성 에이전트가 의미상 관계를 판단하여 `review`에 분류 이유를 남긴다.

문단과 표 제목은 `list:{kind:'number'|'bullet',level:2|3,group:'상위항목별묶음',indent_left_mm:실측값}`으로 지정한다. 숫자는 선택된 `heading_numbering`의 해당 수준을 쓰므로 `가.→1)` 같은 사용자/참고 순서를 유지한다. 같은 번호 묶음은 같은 정의를 공유하고 다른 상위 항목의 묶음은 별도 정의로 시작한다. `bullet`은 실제 `hh:bullet` 가운데점 정의를 쓴다. 표시 문자를 본문 문자열에 직접 붙이는 경로가 아니다.

새 보고서의 의미상 하위 항목에는 각 `paragraph.list` 또는 `table.list`를 사용한다. 종전 `bullets` 블록의 문자열 접두어 경로는 기존 예시의 호환을 위해 남아 있으며 새 하위 항목의 native 번호·내어쓰기 경로로 선택하지 않는다.

공백 폭은 표시되는 문단의 실제 서체·크기 기준으로 계산한다. 11pt 함초롬바탕의 하위 본문은 1칸 330 HWPUNIT, 더 하위는 2칸 660 HWPUNIT이다. 이전 예시의 12pt 하위 제목(360)과 다르므로 제목 크기를 그대로 적용하지 않는다. 왼쪽 여백과 NUMBER/BULLET 수준을 저장하고 번호·글머리표의 `autoIndent=1`을 보존한다. 이어지는 줄의 실제 정렬은 한글 렌더에서 확인한다. 구조 검사에서는 번호 정의·그룹 공유/분리·누락·단계 건너뛰기·위치·자동 내어쓰기 설정을 검증한다.

문서의 목적과 독자가 확인할 판단을 먼저 정한다. 기능을 보여 주려고 항목·설문·예산·표를 추가하지 않는다. 결과보고서에서는 핵심 결과와 보완할 점을 앞에서 짧게 제시하고 뒤의 자료가 그것을 뒷받침하게 한다. 독자와 용도를 추론했다면 `review`에 가정으로 남긴다. 사용자에게 요구하지 않은 결재나 조직의 규칙을 만들지 않는다.

생성기의 사용법, 검증 방법, ‘실제 보고서에서는…’ 같은 제작 설명은 결과물의 본문에 넣지 않는다. 합성 예시는 첫머리에 명확히 표시하고 모든 표·문단마다 합성임을 반복하여 업무 내용을 가리지 않는다. 설문·활동지의 해석 한계는 해당 결과를 이해하는 데 필요한 범위로 한 번 설명한다. 문단마다 하나의 결과·근거·조치를 담고 불필요한 방어 문장을 줄인다.

표는 동일 속성을 비교·대조할 때 사용한다. 개요 두세 줄이나 단순 합계는 표보다 짧은 문장이 나을 수 있다. 표가 같은 숫자를 본문과 반복하거나 열마다 긴 설명이 필요한 경우 정보 구조를 다시 검토한다. 표 수와 글자 수를 품질 목표로 삼지 않는다. 목적이 다른 문서에 같은 보고서 구성을 강제하지 않는다.

`paragraph.emphasis:true`는 핵심 판단 문단만 굵게 표시한다. 표 `columns[].align`에 `left/center/right`를 명시하면 서술 열과 수치 열을 구분한다. 표의 `table_header_align`은 제목 행 정렬, `table_line_spacing`은 셀 줄 간격, `table_paragraph_after_pt`는 셀 문단 뒤 간격이다. 표 셀 여백과 문단 간격을 함께 고려하여 공백을 중복해서 키우지 않는다. 새 표는 제목 문단과 함께 두되 표를 담은 문단은 뒤 문단의 유지 설정을 물려받지 않는다. `table_keep_with_next:false`를 명시하면 저장 구조에서 그 설정도 검사한다. 기본 null은 과거 산출물 감사의 호환 설정이며 새 생성에서는 뒤 문단과 함께 유지하지 않는다.

번호·들여쓰기, 서체·강조, 여백의 선택은 참고에서 실제 측정한 규칙과 새로 선택한 값을 구분하여 기록한다. 제목만 들여쓰고 내용은 원래 왼쪽에 놓는 경우 등 읽기 위계가 연결되는지도 확인한다. 저장값이 타당해도 실제 번호 위치, 표의 팽창, 빈 공간과 쪽 경계는 한글 렌더 없이 확정할 수 없다.

번호 체계는 요청·참고 문서·목적에 따라 고른다. 모든 문서에 같은 단계 순서를 강제하지 않는다. 사용자 지정이 있으면 그것을 먼저 적용한다. 번호를 요청하지 않은 짧은 안내문에 불필요한 다단계 번호를 붙이지 않는다. 기관의 번호 규칙이 중요한데 없으면 그 규칙을 질문한다. 중요하지 않으면 선택한 번호와 들여쓰기의 이유를 `review`에 기록하고 진행한다.

사용자가 ‘최상위 0칸, 하위로 갈수록 한 칸 추가’를 지정하면 번호 순서를 유지하고 그 간격을 실제 서체의 U+0020 공백 폭으로 계산한다. 고정 6mm나 한글 전각 글자 폭으로 대신하지 않는다. 각 수준의 기존 글자 크기·장평·자간도 유지한다. 문단 왼쪽 위치는 0/1/2칸으로 설정하고 선행 공백 문자를 본문에 넣지 않는다. 번호의 자동 내어쓰기 설정을 보존하여 줄바꿈 정렬을 유지하도록 설계하되 실제 번호 시작점과 이어지는 줄의 정렬은 native 렌더 없이 확정하지 않는다. 과거 개발판의 글꼴별 위치 검증 기록은 공개 묶음에 포함하지 않는다. 현재 PC에서는 실제 출력으로 위치를 확인한다.

`design.format` 또는 우선하는 `brief.format`에 아래 속성을 지정한다. 생략하면 기본값을 사용하고, 명시한 미지원 속성은 오류로 중단한다.

| 속성 | 지원과 기본값 |
| --- | --- |
| `heading_numbering` | 기본 `null`. 세 수준의 `{format,text,start}`. `DIGIT`, `HANGUL_SYLLABLE`, `LATIN_SMALL`; `text`는 해당 수준의 `^1.`, `^2)`, `(^3)` 같은 모양. 모든 제목은 한 공유 `hh:numbering` 정의를 참조한다. |
| `heading_layout` | 세 수준마다 `indent_left_mm`, `first_line_indent_mm`(음수 내어쓰기), `spacing_before_pt`, `spacing_after_pt`. 기본 왼쪽/첫 줄 0mm, 제목 앞 10/6/6pt, 뒤 4pt. |
| `character_ratio` / `letter_spacing` | 장평 기본 100%, 자간 기본 0%. 한 쪽에 맞추려고 글자를 임의로 압축하지 않는다. 사용자 지정값을 저장하고 겹침·가독성은 시각 확인한다. |
| `body_spacing_pt` / `line_spacing` | 본문 `{before:0,after:5}`pt / 줄 160%. 단락의 구분과 표 앞뒤 흐름에 맞춰 선택한다. |
| `table_layout` | 기본 `null`(코어 기본 표 동작). 지정하면 `cell_margins_mm` 네 방향, `vertical_align` TOP/CENTER/BOTTOM, `line_wrap:'BREAK'`, `page_break:'CELL'`, `repeat_header:true/false`를 모두 준다. |

번호는 본문에 직접 쓰거나 공백 문자열을 반복하지 않는다. 구조 번호는 사실·예산의 숫자와 구분한다. 자동 번호는 XML 본문 텍스트 추출에 나타나지 않는다. 내어쓰기와 번호 너비에 의한 자동 배치를 함께 고려하고, 실제 줄 정렬은 한글 렌더에서 확인한다.

표 서식은 새로 만든 표와 셀에만 제한된 OWPML 속성을 설정한다. 최소 셀 본문 폭 검사와 저장된 셀 여백·정렬·줄바꿈·제목 반복 설정 검사를 수행한다. 기존 양식의 XML을 수정하는 경로로 사용하지 않는다. 긴 행 높이와 실제 쪽 나눔은 별도 시각 검사 대상이다.

`examples/new-document-realistic/economy-report-formatted`는 `1.→가.`를 공용 계획서의 실제 관행에서 참고했다. 단계별 6mm 추가 들여쓰기는 사용자 요청에 따른 새 설계다. 세 번째 단계 `1)`는 정의만 있고 이 보고서에는 사용하지 않았다. 다른 설계에서 `1)→가.→a.`를 지정하여 구조 시험했다. 참고에서 측정한 값과 새로 선택한 값을 구분한다.

생성 후 페이지 여백·장평·자간·줄/문단 간격·제목 번호·들여쓰기·표 폭·셀 여백·세로 정렬·줄바꿈·쪽 나눔 설정을 읽어 대조한다. 이 검사가 실제 한글의 여백 균형, 글자 간격, 번호 재시작, 표 넘침, 고아 제목, 출력 쪽수를 증명하지는 않는다. COM 및 한글 렌더 검증 경로를 유지하고 차단 시 미검증 항목을 구체적으로 보고한다.
