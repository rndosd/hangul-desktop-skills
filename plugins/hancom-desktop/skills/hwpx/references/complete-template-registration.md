# 완성형 양식 추가·교체

새 원본을 반복해서 채워 쓸 준비본으로 등록하거나, 등록 원본·준비본을 교체할 때만 읽는다. 일반 문서 작성은 [서식 선택](template-selection.md) → [공통 fill](simple-entry.md#준비된-완성형-계획서-채우기)로 진행한다. 등록 준비를 매번 반복하지 않는다.

## 사용자의 짧은 요청에서 시작하기

“첨부한 문서를 기본형으로 만들어줘”는 이 절차의 실행 요청이다. 결과는 다음 작성에서 다시 쓸 수 있는 **준비본·입력 연결·개인 목록·예시 검증**이다. 단순 파일 복사나 “등록했습니다”라는 설명만으로 완료하지 않는다. 기존 기본형으로 한 문서를 작성해 달라는 요청에는 등록을 다시 실행하지 않는다.

파일명과 대화에서 용도·이름을 정하고, 승인된 기존 업무 폴더에 개인 등록본을 둔다. 첨부 파일이 없으면 원본을 요청한다. 저장 위치가 이미 정해졌다면 다시 묻지 않는다. 사소한 입력 필드·명령 선택은 에이전트가 맡는다. 개인 원본을 공개 저장소나 플러그인 캐시에 넣지 않는다.

## 1. 원본과 사용할 범위 정하기

사용자에게 필요한 것은 원본 파일과 주된 용도다. 기존 맥락으로 알 수 없는 경우에만 유지해야 할 부분이나 자주 쓰는 내용을 확인한다. 기술적인 필드·좌표·해시 작성은 에이전트가 맡는다.

- 한 원본의 디자인을 기준으로 준비한다. 전체 원본을 페이지별 블록으로 분해하거나 다른 양식을 섞을 필요는 없다.
- 원본은 보존하고 준비 사본을 만든다. 개인 원본·준비본·목록은 해당 사용자 업무 폴더에 둔다. 공유 견본으로 등록하도록 요청받은 것만 스킬의 공유 목록에 넣는다. 출처와 확인된 이용조건을 남긴다.
- 용도, 주요 내용 구역, 필수로 유지할 부분과 생략 가능한 부분을 짧게 기록한다. 페이지 수는 관측값이며 작성 목표가 아니다. `.hwp`는 필요할 때 [기존 변환 경로](workflows-hwp-conversion-windows.md)로 HWPX 사본을 만든다.

이 단계의 결과는 **원본 후보**다. 보관하거나 목록에 이름을 올린 것만으로 바로 채울 수 있는 양식이 되지는 않는다.

## 2. 준비본과 입력 연결 만들기

기존 [조회·batch·layout](simple-entry.md), [본문 편집](body-structure-edit.md), [표 흐름](existing-table-flow.md)을 사용한다. 현재 공통 실행기에는 완성형 양식을 자동 등록하는 단일 명령이 없다. 양식마다 새 편집 엔진을 만들지 말고, 확인한 구조에 기존 기능을 연결한다.

먼저 원본의 옛 사례 내용·개인정보·불필요한 고정 빈칸을 정리한다. 제목·열 이름·장식·의도적인 선 디자인은 남기며 입력 위치를 준비한다. 빈 준비본에 옛 본문을 남겨 매번 지우게 하지 않는다. 내용이 없어도 필요한 반복 문단·행의 기준 구조는 보존한다.

| 연결할 것 | 준비 방법 |
|---|---|
| 제목·기간·대상 같은 단일 값 | `slots`로 실제 위치와 역할을 연결한다. 표지·요약·본문의 같은 값은 `valueFrom`으로 연결한다. |
| 활동·일정·준비물 같은 반복 내용 | 실제 반복 가능한 문단·행을 `repeats`의 기준으로 삼는다. 내용의 의미에 맞는 구역으로 각각 연결한다. 준비·역할·안전을 하나의 잡다한 반복 칸에 몰아넣지 않는다. |
| 글꼴·정렬·들여쓰기·간격 | 준비본의 역할별 서식을 기준으로 한다. 원본 서식 상속만으로 충분하면 `styles.json`에 불필요한 덮어쓰기를 만들지 않는다. |
| 생략 가능한 구역 | 필요할 때 `preparation.preparedRanges`에 현재 해시와 루트 경로를 묶는다. 이는 위치 색인이며 자동 삭제 옵션이나 임의 페이지 추출 보증이 아니다. |

배치 기준은 [기존 서식 안내](template-formatting.md)를 재사용한다. 같은 위계 제목은 앞에 문단이 오는 경우와 표가 오는 경우의 **눈에 보이는 간격**을 맞춘다. 특정 양식에서 쓴 간격 수치를 다른 양식에 일괄 적용하지 않는다. 표의 같은 역할에는 같은 정렬 기준을 적용하되 모든 셀을 같은 정렬로 만들지는 않는다. 반복 행·내용 길이가 달라져도 불필요한 고정 높이와 빈 문단 때문에 과한 여백이 남지 않는지 준비 단계에서 확인한다.

입력 계약과 지원 범위:

- 값 하나는 줄바꿈·탭이 없는 한 문단 문자열이다. 여러 문단은 반복 항목으로 표현한다.
- 반복 목록의 항목 수 제한과 편집 batch의 명령 수 제한은 서로 다르다. 현재 반복 목록은 최대 100항목이고 batch는 최대 100명령이다. 복제 등을 포함하면 항목 하나가 여러 명령을 쓴다. 고정 `set`만 있는 대량 채움 외에는 자동 분할을 가정하지 않는다. 긴 반복이 필요한 양식만 기준 행·문단과 복제 참조를 유지하는 기존 batch 경로를 확인하고 지원 범위를 기록한다.
- 병합·중첩·제어 개체가 있는 표는 실제 지원 연산을 확인한다. 미지원 구조를 임의로 평탄화하거나 거부된 편집을 raw XML 쓰기로 우회하지 않는다.
- 입력 연결은 의미에 맞게 준비해야 한다. `fill --content`가 모든 새 양식의 의미를 자동으로 알아내는 것으로 간주하지 않는다.

## 3. 대표 내용으로 확인하기

준비본과 **실제 사용할 만한 내용 한 건**을 채운 예시를 한글에서 출력해 본다. 정상 분량의 예시에 반복 증가와 긴 셀 내용이 포함되면 같은 예시로 확인한다. 반복 확장·선택 구역 생략을 주요 기능으로 제공하는데 예시에서 다루지 못했을 때만 그 부분을 추가 시험한다. 모든 길이·모든 조합을 시험하지 않는다.

등록 전 시험에는 기존 `fill_template.compile_fill`과 공통 batch를 사용할 수 있다. 정식 `fill`은 등록 상태와 검증 근거를 검사하므로, 실행을 통과시키려고 미확인 양식에 가짜 `PASS` 증거를 먼저 만들지 않는다.

확인은 [Windows 실제 검증](../../hwpx-windows-finalize/SKILL.md)과 기존 출력 검토로 묶는다. 입력 누락·옛 사례 잔존, 제목과 내용의 대응, 글꼴·정렬·내어쓰기, 제목/표 주변 간격, 잘림·겹침·불필요한 빈 쪽을 해당 출력에서 본다. 준비본에 원인이 있으면 준비본과 연결을 고쳐 같은 예시로 확인한다. 수정하지 않은 동일 출력은 기존 확인 근거를 재사용한다. 눈에 보이지 않는 저장 후 내부 서식 정규화만을 이유로 다시 수선하지 않는다.

검증한 내용·반복량·확인 못 한 변형·필요한 출력 방식을 기록한다. 한 예시의 성공을 모든 분량이나 부분 추출의 성공으로 확대하지 않는다.

## 4. 기존 목록에 연결하기

공유 완성형은 `assets/document-templates/full-plans.json`, 개인 양식은 기존 업무 폴더의 같은 스키마 목록을 쓴다. 이름에 `block`이 있어도 이 목록 스키마는 완성형 문서에도 사용한다. 실제 형식은 [현재 plan-school 연결](../assets/document-templates/full-plans/plan-school/manifest.json)을 참고하되 그 양식의 좌표·해시·합격 기록을 새 양식에 복사하지 않는다.

| 파일 | 기록 내용 |
|---|---|
| 목록 (`hwpx.block-library.v1`) | 고유 ID·용도·짧은 구조 설명, 원본·준비본·PDF·미리보기·fill 참조, 실제 시험 범위와 제약. 확인 전 `draft`, 확인 후 `reviewed`; 중립 준비본은 `neutral_form`. |
| `manifest.json` (`hangul.fill.v1`) | 같은 `blockId`, `sourceDocumentSha256`, `template`, `styles`, `slots`, `repeats`, 필요한 준비 정보와 예시 검증 참조. `sourceDocumentSha256`은 이 목록의 `document` 해시이며 출처 원본 해시와 혼동하지 않는다. |
| `styles.json` | 현재 준비본의 역할별 서식 연결. 텍스트 의미나 양식 선택 규칙을 여기에 중복 기록하지 않는다. |
| 준비본·미리보기·검증 근거 | 준비 HWPX/PDF/PNG, 대표 입력과 채운 예시, 실제 한글 영수증·검토 근거를 기존 양식 폴더에 보관한다. |

목록의 `verification.evidence`는 기존 `hwpx.block-evidence.v1` 계약을 따른다. 실제 확인 후 `outcome=PASS`, ID·원본/문서/PDF/PNG 해시·쪽수·내용 상태·시험 범위를 맞춘다. 준비 채움의 별도 `verification.evidence`는 `PASS_SAMPLE`과 현재 `templateSha256`, 확인한 예시·PDF·실제 검토 근거를 연결한다. 해시 일치가 시각적 합격을 대신하지 않는다.

참조 경로는 **목록 폴더 기준**이다. manifest가 하위 폴더에 있어도 그 폴더 기준으로 바꾸지 않는다. 준비본·서식·미리보기·증거를 확정한 뒤 manifest 참조 해시, 마지막에 목록 참조 해시를 갱신한다. 구조를 바꿨으면 `preparedRanges` 경로와 해시도 갱신한다.

등록 후에는 선택한 실행기의 읽기 전용 조회로 실제 연결을 확인한다:

```powershell
# $taskLauncher는 simple-entry에서 확인한 공통 실행기
$formCatalog = '업무폴더/양식목록.json' # 공유본은 assets/document-templates/full-plans.json
& $taskLauncher fill --catalog $formCatalog --template 등록ID
```

`PREPARED_FORM`과 예상 입력 항목·역할·제약이 나오는지 확인한다. 이는 연결 확인이며 앞 단계의 실제 출력 검토를 대체하지 않는다. 이미 같은 준비본과 입력을 검증했다면 조회 확인을 이유로 같은 문서를 다시 출력하지 않는다.

## 이후 사용과 원본 교체

일반 작성에서는 선택한 한 항목을 조회하고 내용 값을 채운다. 필요한 구성 변경만 기존 편집으로 이어간다.

```powershell
& $taskLauncher fill --catalog $formCatalog --template 등록ID --values 내용.json --output 새계획서.hwpx
```

원본 분석·중립화·전체 서식 준비·등록 검증을 반복하지 않는다. 새 결과는 내용과 분량에 따라 실제 출력을 확인하고, 수정 후에는 영향받은 쪽과 흐름을 다시 본다.

원본이나 준비본을 교체하면 해당 항목의 입력 위치·서식·범위·검증 연결을 다시 확인한다. 같은 파일명이어도 기존 증거를 해시만 바꿔 재사용하지 않는다. 문구만 바뀐 경우와 구조가 바뀐 경우를 구분해 영향받는 부분을 준비하고, 다른 정상 양식을 다시 등록하지 않는다. 문제가 있는 항목은 수정 전까지 준비 완료로 취급하지 않는다.

## 5. 다음 요청에서 다시 찾도록 연결하기

현재 업무의 기존 README·AGENTS·양식 안내 등 재개 입구에 **개인 목록 경로, 양식 ID, 사람이 알아볼 이름·용도, 기본 선택 여부, 확인한 범위**를 짧게 연결한다. 기존 등록 안내가 있으면 갱신하고 같은 내용을 여러 곳에 복제하지 않는다. 입구가 없다면 개인 등록 폴더의 짧은 안내 하나에 기록하고 위치를 사용자에게 알려준다. 이름만 보고 모든 새 대화에서 자동 발견한다고 약속하지 않는다.

여러 개인 양식이 있으면 요청에서 정한 기본 선택을 기록한다. 하나뿐이면 해당 업무의 기본형으로 연결할 수 있다. “기본형 교체”는 지정한 개인 등록본만 갱신하며 기본 제공 3종이나 다른 개인 양식을 임의로 덮어쓰지 않는다. 원본과 이전 검증본은 보존한다.

완료 시 사용자에게 등록 이름·위치, 실제 확인한 대표 예시, 미확인 부분과 함께 **“다음부터 이 업무에서 ‘등록한 기본형으로 ○○ 계획서를 써줘’라고 요청하면 됩니다”**라고 안내한다. 같은 업무를 이어갈 때는 재개 입구에서 찾은 목록·ID로 기존 fill을 실행한다. 지원하지 못한 구조나 실제 출력 검수가 남아 있으면 준비 완료로 보고하지 않는다.
