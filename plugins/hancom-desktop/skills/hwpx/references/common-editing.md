# 자주 쓰는 편집 — 우선순위와 확인 범위

문서 내용을 정해진 목차로 제한하지 않는다. 작업에 필요한 기능만 선택한다.
새 보고서 작성과 기존 문서 편집의 지원 범위를 구분한다.

## 일상 작업의 우선순위

1. 문장 교체·길이 변경·선택 문구 삭제, 중복 문구의 지정 위치 수정.
2. 제목/번호 계층과 설명문 들여쓰기, 글꼴·강조·행간 유지 또는 명시한 부분의 변경.
3. 기존 일반·병합 셀의 내용 수정 및 라벨 기준 빈 양식 채우기.
4. 쪽 나눔, 표 넘김, 제목과 다음 문단 연결, 머리말·쪽 번호.
5. 그림 삽입·교체·크기·캡션·정렬.

이 순서는 개발·시험 우선순위이며 문서에 모두 넣으라는 형식 요구가 아니다.
특수 수식·차트·복잡한 연결 도형은 사용자가 필요로 할 때 다룬다.

## 현재 확인된 기존 문서 편집

2026-10-03, python-hwpx 6.3.0 / 한글 2024 13.0.0.3903에서
한글로 저장한 합성 업무 문서 3쪽을 기존 원본으로 사용했다.
원본→후보 보존 검사, 한글 저장→재열기→PDF 출력, 전체 3쪽 시각 검토와 완료 gate를 통과했다.

- 본문 설명 길이 변경, 여러 서식 run에 걸친 문구 교체, 문구 일부 삭제.
- 중복 본문 중 명시한 위치만 변경; 다른 본문 보존.
- 표의 중복 문구 중 지정 셀만 변경, 일반 셀의 긴 내용, 기존 병합 소유 셀 내용 변경.
- 라벨로 빈 칸 찾기, 기존 두 문단 채우기, 반복 라벨의 순서·개수를 맞춰 입력.
- 번호/문단·글자 서식/표 경계·병합/결재란/기타 내용의 보존.

CLI 0.3.1은 한글이 저장하는 `run charPrIDRef`만 있고 자식이 없는 빈 셀도 지원한다.
form_fill 및 별도 빈 반복 영역 경로에서만 허용하고 public run.text setter로 plain t 하나를 추가한다.
예상 구조에 그 추가만 명시해 전부 비교하며, 컨트롤·필드·중첩 셀·이상 텍스트는 계속 거부한다.
MCP 내부 구현을 바꾼 것은 아니다. 설치된 로컬 CLI를 사용한다.

이는 위 구조의 대표 사례에서 실제 동작을 확인한 것이다. 임의 문서에 자동 보장되는 결과가 아니다.
대상 진단과 요청/비대상 보존 검사, 해당 후보의 필요한 native 검증을 생략하지 않는다.

## 아직 별도 시험이 필요한 편집

기존 문단 삽입·삭제, 글자/문단 서식의 범용 부분 변경, 기존 번호 재설정,
복잡한 표의 행·열 구조 변경·병합/해제, 기존 그림 교체는 기존 본문/양식 시험에 포함하지 않았다. 일반 표의 제한 행 추가/삭제와 너비/높이는 아래 별도 검증을 따른다.
새 문서에서 생성된 요소를 기존 문서에서 안정적으로 편집할 수 있다고 확대하지 않는다.
일반 표의 제한 행 추가/삭제와 셀 크기 변경은 [기존 표 크기 편집](table-layout-edit.md)의 별도 경로로 검증했다. 병합/중첩 표의 구조 변경이나 내용에 따른 자동 맞춤까지 확대하지 않는다.

## 재현 명령

새 작업 폴더를 사용하며 샘플은 업무 문서 템플릿이 아니라 일부러 서식 차이를 둔 합성 시험이다.
Python은 environment.json의 pythonPath를 사용한다. scripts 경로는 현재 hwpx 스킬 기준이다.

```powershell
python -X utf8 scripts/common_edit_benchmark.py build --output-dir new-fixture
# finalize의 verify_hwpx_with_hancom.ps1로 fixture.hwpx를 별도 source-native.hwpx에 SaveAs
python -X utf8 scripts/common_edit_benchmark.py edit --source new-fixture/source-native.hwpx --output-dir new-edits
# edited-candidate.hwpx에 finalize의 prepare → SaveAs → collect → 전체 검토 → check 적용
python -X utf8 -B -m unittest test_safe_edit test_form_fill test_safe_replace test_diagnose_edit test_native_empty_forms
```

작업본과 JSON 영수증은 새 경로만 만들며 기존 파일을 덮어쓰지 않는다.
fixture 포맷 JSON은 시험 재현용이며 일반 보고서의 강제 형식이 아니다.
PC별 COM·DLL 설정은 기존 설치 정책을 따른다. 보안 설정을 시험 코드에서 바꾸지 않는다.

## 기록한 후속 과제

2026-10-03 요청한 내용별 기존 양식 변형은 [기존 양식 변형](form-adaptation.md)의 제한 범위를 검증했다. 기존 입력 칸 높이와 빈 미병합 반복 행 조절·명시적 내역 쪽 나눔을 지원한다. 기준 포함 4사례 전체 6쪽의 결재란/필수 항목/서식 보존과 native 완료를 확인했다. 이미 기입된 반복 행 삭제, 병합/중첩 반복 영역과 범용 자동 맞춤은 후속 과제로 남긴다. 고정 제출 양식을 임의로 바꾸거나 자동 글자 축소를 기본으로 하지 않는다.

새 보고서의 긴 표/제목 유지/간격과 페이지 여백은 [쪽 흐름](page-flow.md)의 별도 검증을 따른다. 기존 임의 양식에서 같은 편집을 안정적으로 수행한다는 뜻은 아니다.

## 쪽 요소와 셀 병합·정렬 추가 검증

필요한 보고서에만 [쪽 요소](report-page-elements.md)를 선택한다. 표지 제외/본문 번호 재시작, 첫 쪽부터 번호, 페이지 추가 시 번호 갱신을 native 확인했다.
기존 plain 표는 [가로 셀 병합·해제와 문단 정렬](cell-merge-alignment.md)의 별도 범위에서 지원한다. 내용이 든 비앵커 셀 병합, 세로 병합과 복잡한 셀은 아직 포함하지 않는다. 기존 양식 변형은 별도 제한 경로를 따르며 복잡한 양식 후속 과제는 유지한다.


## 셀 안 배치 추가 검증

[세로 정렬·안쪽 여백·일반 줄바꿈](cell-spacing-wrap.md)은 별도 도구에서 기존 plain 여러 문단/run과 native 줄바꿈을 보존한다. TOP/CENTER/BOTTOM, 부분 안 여백 변경과 상속 유지, 긴 셀 BREAK 전환을 8편집 사례로 확인했다. 글자 축소나 양식 자동 변형을 기본으로 하지 않는다. 표 앞뒤 여백과 셀 내부 여백은 구분한다.


## 셀 선·채우기 추가 검증

[혼합 테두리·대각선·배경색](cell-borders-diagonals.md)은 방향별 선 없음/종류/두께/색, 일반·병합 앵커 대각선, 단색 채우기와 제거를 별도 보존 경로로 지원한다. 공유 경계는 이웃 셀에도 반영하며 병합 이웃의 부분 변은 거부한다. 기존 서로 다른 테두리에 같은 배경색을 넣는 문제를 이 새 경로에서 막았다. 편집 9종·기준 1종 전체 12쪽의 실제 한글 검증을 마쳤으며, 임의 셀의 대각선 글자를 자동 재배치하는 기능은 포함하지 않는다.


## 기존 긴 표의 쪽 흐름 추가 검증

[기존 표 쪽 흐름](existing-table-flow.md)은 미병합 plain 표의 제목행 반복·CELL/TABLE 나눔·선택 앞뒤 간격과 바로 앞 제목의 명시적 쪽 나눔을 별도 보존 경로로 다룬다. 편집 7종·기준 2종 전체 29쪽을 native 확인했다. 제목 keepWithNext/앵커 연결만으로 순서가 잘못된 3개 진단 사례는 거부했고 명시한 제목 문단의 쪽 나눔으로 바로잡았다. 과한 표 간격을 줄인 사례는 글자/쪽 여백을 그대로 두고 2쪽을 1쪽으로 줄였다. 이 미병합 경로에는 기존 양식의 범용 자동 여백 맞춤이나 병합 제목행을 포함하지 않는다.


## 다단 병합 머리글 추가 검증

[다단 병합 머리글](merged-table-headers.md)은 최상단 1~3행 안에서 끝나는 기존 가로·세로 병합을 유지하며 정렬·셀 안 여백·각 단 높이·전체 제목행 반복을 선택 편집한다. 2단/3단 기준 2종과 편집 5종, 전체 14쪽에서 실제 저장·재열기·PDF·strict gate를 통과했다. 문구 한 곳의 변경은 기존 safe_edit의 소유 셀 선택 경로로 검증했다. 본문과 테두리를 보존하며 기존 세로 재병합이나 본문까지 걸친 병합을 지원하는 것은 아니다. 목차/내용과 머리글 단 수를 강제하지 않는다.


## 어절 보존과 긴 표 내용

[어절과 긴 표](word-flow.md)를 선택 적용한다. 한글 어절·영문 단어 줄바꿈을 우선 비교하고, 과한 빈 공간이 있는 문단에만 소폭 자간 후보를 본다. 78mm 열은 0→-1로 긴 어절이 앞줄에 들어갔지만 75mm 열의 -3/-4는 효과가 없었다. 자간·장평·최소 공백은 별개이며 모든 문단을 꽉 채우도록 강제하지 않는다. 여러 문단/목록을 지키는 열 재배분은 별도 safe_table_columns 경로다. 내용과 서식을 지킨 6종·17쪽, 43개 가드를 확인했다. 원본 글자 나눔 기준과 잘못된 새 목록 들여쓰기 초안은 진단 실패로 남겼다.


## 소계·합계와 숫자 표시 추가 검증

[소계·합계](summary-rows.md)는 선택한 기존 셀의 굵기/LEFT·CENTER·RIGHT 정렬, 값 보존 천 단위 구분/소수 표시와 별도 배경/구분선을 지원한다. 병합 소계 제목과 두 문단 셀을 유지한 실제 5사례·6쪽을 검증했다. 총합계 고립과 keepWithNext 실패를 별도 차단하고 선택한 과한 안 여백을 줄여 2쪽을 1쪽으로 회복했다. 반올림·단위 환산·수식·자동 행 묶기나 모든 보고서의 고정 디자인은 추가하지 않았다.


## 내용에 맞춘 공통 구조 설계

[공통 구조 설계](content-structure.md)는 원자료와 관계·표현 선택을 새 문서와 호환 기존 양식에 공유한다. 설명/작업 순서/비교의 세 쌍에서 문단·native 항목·표, 기존 빈 행 조절·가로 병합·머리글/열 너비 변경을 확인했다. 기존 원문/결재란 보존과 실제 출력 검토를 연결하며, 기입된 영역의 자유로운 재구성은 후속 과제다. 보고서 내용/목차와 특정 구조를 강제하지 않는다.


## 공식 기능 추가 검증

[선택 개체 작성과 그림 교체](official-report-features.md)에서 새 native 그림 캡션·각주/미주·책갈피·웹 링크·요약 상자와 단일 비공유 PNG/JPEG 데이터 교체를 별도 구현·검증했다. 기존 그림 교체가 위 본문/양식 시험에 포함되지 않았다는 기록은 유지하며 이 제한 경로만 추가한다. 독립 번호/글머리표 생성도 native로 수정했다. 고정 시험 사본의 항목 추가·삭제/자동 번호/내어쓰기는 확인했지만 일반 기존 목록 편집 명령은 구현하지 않았다.

## 혼합 서식을 유지한 본문 편집
