# 기존 쪽 번호·첫 쪽 표시 설정

native_page_settings_cli.py inspect → 정확한 sourceSha256/binding 요청 → apply --dry-run → apply를 사용한다. schema는 hwpx.native-page-number.v1. 기존 한 구역의 숫자 쪽 번호, 하단 LEFT/CENTER/RIGHT, 구역 시작값, 이미 있는 PAGE 재시작, 첫 쪽 머리말·꼬리말·번호 표시만 지원한다. 다른 번호 형식·여러 구역·새 번호 제어 삽입은 미검증이다.

HWPX 검사와 실제 출력 검사는 별개다. 한글 저장 전후 활성 구조·전체 서식 정의·native 번호 제어 값을 비교하고 저장본에서 같은 설정을 다시 바꾼다. 첫 쪽 숨김 및 본문 재시작에 따른 실제 번호 순서를 원본의 상세 요청으로 확정한다. 번호가 다른 쪽 요소와 겹치는지는 PDF의 실제 글자 위치로 확인한다. PDF가 저장 전후 같아도 충돌은 실패다. RIGHT 번호와 RIGHT 꼬리말의 겹침이 재현됐다. 기존 요소를 임의로 숨기거나 번호 위치를 바꿔 통과시키지 않는다. 명시한 관련 배치 수정 및 비대상 보존 검증이 필요하다.

HWP045: 2문서 첫 저장·반복 저장·동일 설정 재편집 활성 구조/전체 헤더 정의 PASS, 저장 전후 PDF 픽셀 동일. 표지 표시/본문 번호 재시작 통과. 일반 문서 RIGHT 재편집의 꼬리말 충돌은 FAIL. 10 native 작업, 9 요청 가드, 12쪽 직접 검토. 설치본 교체/보안 설정 변경 없음.
