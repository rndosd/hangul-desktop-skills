# 새 문구를 기존 서식 조각에 매핑하기

표의 새 행/분할 셀 또는 기존 문구를 바꿀 때 먼저 문단에 들어갈 전체 문구를 정한다. 같은 문구를 모든 run에 통째로 넣으면 출력이 반복된다. 문단 수와 run 수는 내용 항목 수가 아니다. 단순한 사용자 요청을 받더라도 대상 셀과 보존할 기존 문구, 새 문구를 구분해서 결정한다. 내용 구성은 보고서 문맥에 맞춰 판단하고 고정 양식으로 강제하지 않는다.

`paragraph_run_payload.plan(runs, [시작run,끝run], text, segments=None)`은 1부터 세는 연속 run 범위에 하나의 의도한 문구를 넣는다. 범위가 한 run이면 text 하나로 매핑한다. 여러 run이면 글자 서식의 역할에 맞게 segments를 명시한다. 예: runs=['가상 공동취합','가상 공동취합'], span=[1,2], text='증빙 자료 취합', segments=['증빙 ','자료 취합']. 조각을 합친 결과가 text와 정확히 같아야 하며 선택 밖의 접두어·글머리표·단서 문구는 유지한다. '반복 반복'처럼 의도한 반복 자체는 유효하다. 중복을 정규식으로 지우거나 모든 run에 같은 문구를 복사하지 않는다.

run 값은 현재 원본 셀에서 읽는다. mapper는 파일·COM을 만지지 않는 순수 계획기다. XML/컨트롤/보호셀의 지원 범위는 실제 편집 엔진이 따로 검사한다. 기존 글자 서식을 가진 nonempty run을 비우는 계획, 조각 수/전체 문구 불일치, 선택 밖 변경, 겹치는 규칙은 거부한다. 여러 서식 조각에 들어갈 문구가 너무 짧다면 서식 변경의 의도를 별도로 정한다. 잘못된 내용을 반복 제거로 추측하지 않는다.

`map_cell(rich.cell_model(cell), rules)`은 현재 셀의 전체 문단→run 문자열 지도를 만든다. 각 rule은 paragraph/span/text/선택적 segments이며 같은 run에 두 규칙을 겹치지 않는다. 새 행의 각 셀에 이를 적용해 완전한 cells 지도를 구성하고, [부분 표 구조 편집](mixed-table-structure.md)의 hash/table-ID/fingerprint를 묶은 clone_after 또는 unmerge 경로에 넘긴다. 기존 run의 attrs나 bullet/fwSpace를 mapper가 새로 만들지 않는다. 셀 내용을 표 전체 텍스트로 flatten하지 않는다.

기존 단순 run 문구를 고칠 때는 [선택 텍스트 편집](selected-text-edit.md)으로 원본 해시와 표/행/열/문단/정확한 run 시작 위치를 묶는다. 동일 문자열이 여러 run에 있으면 전체 find 일괄교체를 하지 말고 각각의 정확한 run 범위를 지정해 새 조각을 넣는다. 전체 중복 문단을 한 덩어리로 줄여 뒤쪽 run 서식을 지우는 식의 자동 처리는 하지 않는다. fwSpace 등 컨트롤을 포함한 문단에는 plain selected-text 경로를 확장하지 않는다.

JSON 순수 계획 확인은 `scripts/paragraph_payload_cli.py --request REQUEST.json`. schema=hwpx.paragraph-payload.v1, runs=기존 문자열 목록, span=[시작,끝], text=의도한 전체 문구, segments=선택한 각 run의 새 조각. 출력은 전체 문자열 지도이며 문서 저장/COM 실행 성공을 뜻하지 않는다. 편집 적용 뒤에는 현재 원본의 독립 전체-package 기대값과 실제 문단 전체 문자열·모든 run 서식을 대조한다. 새 문자열을 생성한 함수 자체에서 기대값까지 만들지 않는다.

실제 한글 저장본을 열고 PDF로 출력하여 전체 문구의 횟수와 표 안 여백/잘림을 확인한다. 실제 저장본에 같은 문구 매핑 또는 행 추가를 다시 적용해 후속 편집도 확인한다. 저장 전후 PDF, 내부 적용 서식, 모든 공유 정의와 raw 차이는 각각 기록한다. 이 경로는 문구를 복제하지 않도록 하는 기계적 검사다. 문맥에 따른 최선의 스타일 분류, 모든 문서/PC/버전 호환성을 증명한 것은 아니다.
