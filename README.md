# 한글 데스크톱 스킬

Codex에서 짧은 요청으로 HWPX 문서를 작성하고, 기존 문서의 본문·표·서식을 편집하며, 설치된 Windows 한글로 실제 출력을 확인하는 커뮤니티 플러그인입니다. **0.1.0-beta.1** 공개 베타입니다. 한컴 또는 OpenAI의 공식 제품이 아닙니다.

보고서의 내용이나 목차를 고정하지 않습니다. 요청에 맞는 구성·번호 계층·표·간격을 선택하고 원자료, 비대상 서식, 실제 지면을 구분해 확인합니다. 원본을 덮어쓰지 않습니다.

**처음 사용한다면 [설치부터 첫 문서까지: 사용자 설명서](docs/getting-started.md)를 먼저 읽으세요.** ZIP 다운로드, PowerShell 여는 법, 설치 결과 해석, 첫 요청, 보안 모듈 선택과 오류 해결을 순서대로 설명합니다.

**원본이 HWP라면:** [한컴 공식 HWPX 변환기 다운로드 센터](https://www.hancom.com/support/downloadCenter/download)에서 **추가 기능(Add-In) → HWPX 변환기 → 패치파일 → 다운로드**를 선택하세요. 한컴이 무상 제공하는 별도 프로그램이며, 설치된 한글이 필요합니다. [변환기 설치·사용 안내](docs/getting-started.md#원본이-hwp일-때-공식-hwpx-변환기)는 원본 보존, 준비 조건과 변환 후 확인 방법을 설명합니다. 현재 공통 편집 도구의 HWP 자동 변환 연결은 미검증이므로, 변환한 HWPX를 입력하는 방법을 안내합니다.

## 두 가지 사용 방식

| 방식 | 제공할 자료 | 예시 요청 |
|---|---|---|
| 기존 양식 사용 | 원본 HWPX와 넣거나 바꿀 내용 | “이 보고서 양식으로 AI 교육 결과보고서를 써줘. 제목·본문·표·목차를 바꾸고 기존 서식은 유지해줘. 내용은 가상으로 표시해줘.” |
| 빈 문서에서 작성 | 메모·자료·주제, 필요한 분량과 조건 | “이 메모로 팀 회의 결과보고서를 한글로 만들어줘. 결정 사항과 담당자·기한을 정리하고 필요한 표를 넣어줘.” |

기존 양식은 해당 문서의 제목·문단·표·서식을 분석해 필요한 위치를 수정합니다. 특정 동봉 양식 전용이 아니며 내용에 따른 제한적인 행 추가·삭제·크기 조정도 지원합니다. 양식 유지 요청에서는 원래 배치를 기준으로 하고, 구조 변형이 필요한 경우 지원되는 연산과 보존 범위를 확인합니다. 복잡한 중첩 표·개체를 임의로 평문화하지 않습니다.

빈 문서 작성은 고정 목차나 개조식만 쓰는 방식이 아닙니다. 요청과 내용에 맞춰 구성·번호 계층·표·문체·간격을 선택합니다. 실제 수치와 담당자는 자료에서 확인하고 미정·제안·가상을 구분합니다. 두 방식 모두 인쇄/제출에 필요한 실제 지면 확인은 별도로 수행합니다.

## COM과 보안 모듈은 무엇인가요?

**COM**은 이 PC에 설치된 한글을 프로그램에서 호출하는 Windows 연결 방식입니다. 한글 엔진으로 문서를 열고, 필요할 때 저장·재열기하며 PDF를 출력하는 데 사용합니다. 플러그인 자체가 한글 프로그램을 포함하거나 클라우드에서 한글을 실행하는 것은 아닙니다.

**보안 모듈 DLL**은 한글 자동화의 파일 접근 검사에 연결하는 별도 구성 요소입니다. COM이 생성돼도 모듈 이름·등록 경로·파일·호환성이 맞지 않으면 `RegisterModule`이 실패할 수 있습니다. 파일 접근 승인창을 줄이기 위한 공식 예제를 선택할 수 있지만, 그 소스의 허용 범위는 작업 폴더가 아니라 모든 요청 경로입니다. 아래의 명시적 선택 절차와 [정확한 출처·등록값·복구 방법](docs/security-module.md)을 확인하세요.

HWPX 내용 작성·정적 검사는 COM 없이도 수행할 수 있습니다. 다만 이 배포본은 검토된 모듈이 준비되지 않으면 실제 한글 COM 문서 작업을 차단합니다. **스킬 설치 → COM 생성 → 보안 모듈 등록 → 문서 열기/저장/출력 → 내용·서식·지면 검수**는 각각 별개의 확인 단계입니다.

Claude Code의 스킬 형식과도 호환되는 구조이나, 현재 배포 검증은 Codex 기준입니다. Windows Claude Code에서 연결하는 수동 절차와 미검증 범위는 [사용자 설명서의 Claude 안내](docs/getting-started.md#claude-code에서-사용하려면)를 참고하세요.

## 다른 PC에 설치

Windows x64와 정상 설치·활성화된 한컴 한글이 필요합니다. 현재 공식 보안 모듈 설치 경로는 **x86 한글**용입니다. 한글 프로그램과 라이선스는 포함하지 않습니다. Python 3.12 및 검증한 패키지 버전을 사용합니다.

[베타 릴리스](https://github.com/rndosd/hangul-desktop-skills/releases)에서 ZIP을 내려받아 압축을 풀고 해당 폴더의 **일반 Windows PowerShell**에서 먼저 진단합니다. 새 문서 작성에는 Windows의 맑은 고딕이 필요하며 다른 버전은 현재 PC의 글꼴 메타데이터를 읽어 사용하고 실제 한글 출력은 별도로 확인합니다.

```powershell
.\Install.ps1 -CheckOnly
```

진단은 경로·패키지·한글 설치 상태를 읽습니다. COM 실행, 레지스트리 변경, DLL 설치, 다운로드, 스킬 교체를 하지 않습니다. 진단 성공은 문서 자동화 성공을 뜻하지 않습니다.

보안 모듈을 새로 등록하지 않는 기본 설치:

```powershell
.\Install.ps1
```

현재 사용자 또는 `CODEX_HOME` 아래에 Python 환경과 두 스킬을 준비합니다. 필요한 경우 고정 버전 uv와 Python 3.12를 다운로드하고 전용 venv에 의존성을 설치합니다. 시스템 PATH·실행 정책·ACL은 바꾸지 않습니다. 기존 스킬은 별도 백업합니다. 이미 사용자가 검토한 같은 PC의 모듈 설정은 재검증 후 유지할 수 있습니다. 등록된 DLL이 있다는 이유만으로 자동 선택하지 않습니다.

다운로드 없이 기존 Python으로 설치하려면 다음과 같이 지정합니다.

```powershell
.\Install.ps1 -PythonPath 'D:\tools\hangul-python\Scripts\python.exe' -NoDependencyInstall
```

경로는 사용 중인 Python 3.12 경로로 바꾸세요. 의존성이 없으면 준비 미완료 상태를 보고합니다. PowerShell에서 실행이 차단되면 조직 정책/파일 신뢰 절차를 확인하세요. 설치기가 실행 정책을 변경하거나 우회하지 않습니다.

## 승인창 없는 자동화를 선택할 때

한컴 **공식 Automation 예제 모듈**의 소스는 요청된 파일 경로를 모두 허용합니다. 전용 작업 폴더만 허용하는 모듈이 아닙니다. Windows 사용자 권한은 계속 적용됩니다. 해시 확인은 배포 파일의 일치만 확인하며, 동봉 소스와 바이너리의 동작 동일성을 독립적으로 증명하지 않습니다.

이 범위를 이해하고 해당 PC에서 사용하기로 선택한 경우, 한글 문서를 저장하고 한글을 정상 종료한 뒤 실행합니다.

```powershell
.\Install.ps1 -AcceptGlobalFileAccess
```

이 **명시적 선택**만 공식 원본 다운로드·SHA256/x86 확인·현재 사용자 HKCU 등록·로컬 승인 기록 생성을 허용합니다. 기본 설치에는 실행되지 않습니다. DLL을 이 저장소에 재배포하지 않고 한컴 공식 저장소에서 받습니다. 출처/해시가 바뀌거나 x64 한글이면 등록을 중단합니다. 설치를 받아서 쓰는 사람의 동의를 다른 PC로 복사하지 않습니다.

정확한 출처, 등록 인자, 변경·복구 방법은 [보안 모듈 정책](docs/security-module.md)을 확인하세요. 기관 전용 모듈을 사용하는 PC는 그 모듈의 출처와 허용 범위를 검토한 뒤 기존 등록을 선택할 수 있습니다.

## Codex 플러그인으로 불러오기

저장소 루트에는 `.agents/plugins/marketplace.json`, 플러그인에는 `plugin.json` 및 `skills/`가 있습니다. Codex CLI가 설치되어 있다면 내려받은 폴더에서 마켓플레이스 소스를 추가합니다.

```powershell
codex plugin marketplace add rndosd/hangul-desktop-skills
```

그다음 데스크톱 앱의 플러그인 설치 화면에서 `hancom-desktop`을 설치하고 새 대화에서 사용합니다. 플러그인 설치와 PC 의존성 준비는 별개입니다. 웹에서 플러그인을 불러오는 것만으로 Windows 한글 COM을 실행할 수 없습니다. [공식 플러그인 패키징 안내](https://developers.openai.com/plugins/build/plugins)를 기준으로 구성했습니다. 공개 디렉터리 등록/심사를 마친 제품은 아닙니다.

ZIP 설치기의 두 스킬 설치 방식과 플러그인 방식 중 하나로 사용할 수 있습니다. 플러그인 캐시에서 실행하는 도구도 이 PC의 `CODEX_HOME/skills` 설정을 읽습니다. 캐시에 이전 PC 설정을 넣지 마세요.

## 사용 예

- “이 메모로 팀 회의 결과보고서 한글로 만들어줘. 결정 사항과 담당자·기한은 보기 좋게 정리해줘.”
- “이 보고서에서 완료된 업무를 지우고 새 점검 업무를 추가해줘. 기존 번호와 표 서식은 유지해줘.”
- “표 앞뒤 간격을 확보하고 큰 번호 항목 시작은 조금 더 띄워줘. 한글에서 실제 출력도 확인해줘.”

`hwpx`는 공통 진입 도구로 작성·편집을 실행하고 `hwpx-windows-finalize`는 실제 한글 열기/PDF, 필요할 때 저장·재열기를 확인합니다. COM 생성, 보안 모듈 등록, 문서 보존, 시각 검수는 각각 보고합니다. 인쇄/제출 문서는 실제 출력 검수까지 필요합니다.

## 확인 범위와 기여

다른 PC 전체에서 인증된 제품은 아닙니다. 복잡한 병합/개체·특정 한글 버전의 native 편집·OLE·저장 정규화에는 지원 경계가 있습니다. [확인 범위와 제한](docs/known-limits.md)을 먼저 참고하세요. 과거 실패를 숨기거나 구조 검사 성공을 실제 출력 성공으로 바꾸지 않습니다.

개발 검증: `python -B tools/verify_release.py` 및 `python -B tools/run_tests.py`. 순수 HWPX/설치 검사는 한글 COM 없이 실행합니다. 실제 출력은 사용자의 PC에서 별도 검증해야 합니다. 개인정보가 포함된 문서·로그·설치 승인 기록은 이슈에 올리지 말고 합성 사례와 오류 단계만 공유하세요.
