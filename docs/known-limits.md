# 공개 베타 확인 범위

확인 기준은 요청 내용, 비대상 보존, 전달한 한글 파일의 실제 출력입니다. 내부 XML 바이트 전체가 저장 전후 동일해야 한다는 목표는 아닙니다. PDF가 같아도 활성 서식·연결 주소·개체·후속 편집 손실이 있으면 별도 문제입니다.

| 범위 | 현재 상태 |
|---|---|
| 공통 진입: 단건 문구 치환, 업무 표 행 추가/삭제, 새 문서 생성 | 기존 guarded 엔진을 유지. 순수 HWPX 회귀를 공개 묶음에서 실행 가능 |
| 짧은 프롬프트 작성 | 여러 개발 사례에서 확인. 모든 프롬프트·모델의 성공 보장은 아님 |
| 복합 편집 | 전문 도구 및 보존 계약을 유지. 작은 모델에서 복합 요청 시간 초과 사례가 남음 |
| 실제 한글 출력 | Windows 한글 및 검토된 보안 모듈 필요. 현재 PC의 런타임 성공은 다른 PC 인증이 아님 |
| x64 한글 | 설치 탐지는 가능. 고정 공식 예제 DLL은 x86이므로 자동 등록 차단 |
| 여러 한글 빌드 | 버전에 묶인 편집은 가드 유지. 다른 빌드에 대해 범용 성공을 주장하지 않음 |
| 새 문서 글꼴 | 현재 PC의 맑은 고딕 SFNT 이름·지원 PANOSE·테이블 경계를 읽음. 기존 PC 해시와 다른 버전은 실제 native 검증 미완료로 기록. 없는 글꼴·다른 family·지원 밖 PANOSE는 거부 |
| Native SplitRowGroup | 과거 PC의 선택 검증 영수증을 배포하지 않음. 공개본에서는 UNVERIFIED_BUILD로 차단될 수 있음 |
| 표 높이 및 미사용 정의 저장 정규화 | 실제 지면 유지와 엄격 내부 비교 결과를 분리. 기존 FAIL을 소급 PASS로 바꾸지 않음 |
| OLE 차트 | 내부 데이터 차이/검증 한계가 남음. 실제 문서·출력 보존이 확인되는 범위에서만 전달 |
| 중첩 셀 전체 쓰기 | 하위 내용 손실이 재현되어 지원하지 않음. 제한 대상/run 편집 사용 |
| 선택적 구형 PDF 텍스트 감사 | `audit_existing_pdf.py`는 pypdf가 없으면 미검사. 기본 PyMuPDF 출력/레이아웃 검증과 별도 |
| HWP 입력 및 OCR | 이 베타의 독립 reader/OCR 설치는 포함하지 않음. HWPX 중심 |

이 저장소에는 편집/검증 코드와 필요한 참조를 포함하고 개발용 대형 문서 모음·개인 양식·타 기관 보고서 원본·기존 PC 환경/승인 기록을 넣지 않습니다. 과거 합격 횟수는 공개본의 새 검증 결과로 사용하지 않습니다. 일부 개발 도구는 제외한 실험 자료를 요구하므로 일반 사용자 경로로 안내하지 않습니다.

배포 확인은 파일 무결성·개인 경로 제거·라이선스·PowerShell 구문·설정 경로 선택·공통 도구 회귀·격리된 설치/백업을 대상으로 합니다. 공식 모듈의 네트워크 다운로드/등록 및 새 PC 실제 COM은 사용자가 별도로 선택하고 확인해야 합니다. 공개 디렉터리 심사 또는 전 기능 인증을 뜻하지 않습니다.
