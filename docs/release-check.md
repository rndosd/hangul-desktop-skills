# 0.1.0-beta.1 배포 검사 — 2026-10-05

## 2026-10-23 시작 지침·중복 설명 정리

원인: 원본 선택·변형과 표 가독성 기준이 진입점·여러 참조에 반복됐고, 과거 범용 빈 서식 안내와 상세 경로의 우선순위 문구가 현행 진입점과 혼재했습니다.

변경: 필수 경로·보존·실패·보안·완료 조건은 진입점에 남기고 원본 재사용 세부는 `source-template-reuse.md`, 표 밀도·간격은 `template-formatting.md`, 실제 출력 검수는 finalize의 `acceptance-policy.md`로 모았습니다. 과거 서식 선택 안내는 현재 `template-selection.md`로 연결하고, 상세 경로는 진입점을 보충하도록 우선순위를 통일했습니다. 실행 코드·서식·기능별 지원 경계·검수 gate는 변경하지 않았습니다.

- 진입점 문자 수(LF 기준): hwpx 6,414→3,510(45.3% 감소), finalize 2,749→2,354(14.4% 감소), 합계 약 36% 감소. 조건별 참조로 옮긴 분량을 포함한 전체 스킬의 감소율은 아닙니다.
- 두 스킬의 skill-creator 기본 검사, 패키지 무결성 검사, 변경 문서의 로컬 링크·절 앵커 138개 확인 PASS. 첫 기본 검사는 실행 환경에 PyYAML이 없어 미실행됐으며, 이미 PyYAML이 있는 기존 Python 환경으로 두 스킬 모두 통과했습니다.
- 기존 회귀 29개 PASS. 실행 파일·vendor·보관 원본·미리보기의 변경은 없습니다.
- 실제 설치본의 변경 전 해시를 확인한 뒤 지침 8개를 관리본과 동기화하고 바이트 해시 일치를 확인했습니다. 두 environment.json은 변경 전후 동일합니다.
- 독립 비교 검토에서 원본 부재 시 한계 안내 누락 한 곳을 복원했습니다. 별도 에이전트가 지정 셀의 중복 문구 수정, 원본 미확보 보고서 작성, COM/저장 실패의 제출 검수 세 상황에서 경로·보존·중단·시각 검수 기준을 찾아 설명했습니다. 이 검토는 문서 읽기 기반이며 실제 한글 실행 시험은 아닙니다.
- 실제 문서 결과의 가독성 개선이나 새 PC native 실행 성공은 이번 정리에서 측정하지 않았습니다. 다음 관련 문서 작업에서 필요한 참조를 선택하고 기준을 빠짐없이 적용하는지 확인합니다.

설치 시험은 한글과 공백이 있는 신규 경로 및 기존 Python 3.12.14에서 수행했습니다. 두 스킬에 동일한 새 PC 설정을 생성하고 보안 선택 없이 nativeStatus는 blocked_security_module인 것을 확인했습니다. `-CheckOnly`와 보안 모듈 동의 없는 호출은 대상 디렉터리도 만들지 않았습니다. 레지스트리·실행 정책·ACL·사용자 설치 스킬은 변경하지 않았습니다. 설치/회귀 PASS가 새 PC의 실제 한글 출력 성공을 증명하지 않습니다.

첫 샌드박스 회귀는 Python TemporaryDirectory의 Windows 접근 거부로 6개가 실행 오류였습니다. 경로 선택 테스트를 작업 공간의 새 디렉터리로 좁히고, 기존 합성 문서 회귀는 승인된 일반 사용자 실행 맥락에서 확인했습니다. 이 최초 오류는 기능 FAIL과 구분합니다.

최초 설치 검사는 샌드박스와 승인된 일반 사용자 맥락 양쪽에서 Python 자식 Windows PowerShell의 Get-FileHash 누락으로 실패했습니다. 직접 Windows PowerShell 호출에는 명령이 존재했습니다. Python 자식이 다른 버전 PowerShell의 모듈 경로를 먼저 상속하는 차이를 관찰했고, 설치 해시를 기존 .NET SHA256 helper로 계산하게 바꾼 후 격리 설치가 통과했습니다. 전역 PSModulePath나 실행 정책 변경은 하지 않았습니다. uv ZIP 해제도 .NET으로 처리하며 실행할 uv.exe를 고정 원본 ZIP 항목의 해시와 대조합니다. 다운로드 경로 자체의 이번 신규 실행 검증은 미완료입니다.

공개 자동 검사로 재현할 수 있는 범위와 native 검증이 필요한 범위는 [지원 제한](known-limits.md)에 나눠 기록했습니다.

최초 [GitHub Actions 실행](https://github.com/rndosd/hangul-desktop-skills/actions/runs/37327071985)은 Windows Server 2025의 다른 Malgun 파일 해시 때문에 새 문서 생성 1개가 실패했습니다. 패키지 검증·6개 경로 검사·나머지 공통 검사 15개는 통과했고 이후 설치 단계는 실행되지 않았습니다. 이 실패 기록을 유지합니다. 현재 PC 글꼴의 family/PANOSE와 SFNT 경계를 검사해 메타데이터를 읽는 방식으로 수정했습니다. 이전 해시와 다른 글꼴은 native 검증 미완료로 표시하며 한글 실제 출력 가드를 제거하지 않습니다. 수정 후 로컬에서는 34개 회귀가 통과했습니다. 별도 Windows 환경의 후속 CI 결과는 GitHub Actions에서 확인할 수 있습니다.

두 번째 [GitHub Actions 실행](https://github.com/rndosd/hangul-desktop-skills/actions/runs/37327936095)에서는 회귀 34개가 모두 통과했으나 Windows PowerShell 5.1 구문 단계에서 UTF-8 BOM 없는 한국어 launcher를 ANSI로 읽어 실패했습니다. 해당 파일에 BOM을 추가하고 공개 검사에서 비ASCII PowerShell의 BOM을 요구합니다. 구문 검사를 생략하지 않으며 후속 CI로 격리 설치도 확인합니다.

## 0.2.0-beta.1 — 2026-10-28

현재 사용자 관리 스킬의 공통 실행기·역할별 표 서식 연결·완성형 계획서 3종과 등록 안내를 반영했습니다. 기본 작성은 한 원본의 디자인을 이어 필요한 부분을 채우며, 옛 원본·합본·부분 블록은 기본 선택과 배포에서 제외했습니다. 제목 위계별 간격과 입력 위치 준비를 재사용합니다.

개인 학교 양식과 PC별 환경·승인 설정은 포함하지 않았습니다. 공개 자료의 기존 출처·이용조건은 유지하며 코드 라이선스를 원본 문서에 일괄 적용하지 않습니다. 로컬 경로는 배포용 상대경로/비식별 표기로 바꾸고 관련 참조 해시를 갱신했습니다. 예시 검토 기록은 기존 PC에서의 근거이며 다른 PC의 한글 출력 성공을 뜻하지 않습니다.

패키지 회귀 26개 통과(설정 6, 글꼴 9, 공통 편집 8, 안전 치환 3). 최초 샌드박스 파일 경로 권한 오류 후 일반 사용자 맥락에서 동일 검사를 통과했습니다. 새 PC COM/레지스트리 검사는 실행하지 않았습니다.

## 2026-10-29 기본형 정리

기본 제공을 plan-school / plan-education / plan-project 3종으로 통일했습니다. 선택기와 공통 fill의 기본 목록을 변경하고 옛 원본·합본 ID를 거부합니다. 불필요한 옛 자산 487개를 배포 대상에서 제외했으며, 완성형 준비본·입력 연결·검증 자료와 필요한 출처 원본 3개를 보존했습니다. 개인 양식은 개인 업무 폴더에서 별도 등록합니다. README와 사용자 설명서에 기본형 미리보기 및 등록 요청문을 연결했습니다.

현재 PC의 설치 스킬과 배포 준비본 양쪽에서 기본 목록 3종, 각 기본형 PREPARED_FORM 및 참조 해시, 옛 ID 거부, 사용자 원본 복사와 기존 출력 덮어쓰기 거부를 확인했습니다. 실제 한글을 다시 실행하거나 새 문서를 조판한 검사는 아니며 준비본 파일은 변경하지 않았습니다.

이번 정리 후 회귀 29개(기본형 선택·입력·옛 자산 제외 3개 추가)가 통과했습니다. 설치·백업 검사는 별도 실행 결과를 확인합니다.

격리 설치 8항목 PASS. 새 vendor 하위 경로로 기존 시험 폴더가 PowerShell 5.1 경로 제한을 넘은 실패를 보존하고, 짧은 임시 경로에서 같은 검사를 완료했습니다. Windows TEMP의 8.3 별칭은 실제 경로로 확정하여 비교합니다. 설치기 변경·전역 긴 경로 설정 변경·보안 모듈 등록은 하지 않았습니다. 현재 PC 및 공개 스킬 quick_validate PASS.
